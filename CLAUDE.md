# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Breach Team is a real-time, top-down tactical shooter (a player plus AI teammates) written in plain HTML5 Canvas and vanilla JS. It has no dependencies, no build step, no package manager, no tests and no linter. All graphics (`js/sprites.js`) and sounds (`Sound` in `js/util.js`) are generated procedurally; there are no asset files. The UI text, code comments and the README are in French, so keep new player-facing strings and comments in French.

## Running

Open `index.html` directly, or serve the folder:

```
python -m http.server 8000
```

Then go to http://localhost:8000. Append `#nobrief` to the URL to skip the mission briefing overlay; this is useful when iterating. Run the regression suite by opening `tests/index.html` (see **Tests** below), then check the change by playing in the browser.

The game is deployed on Render as a static site from `render.yaml`. Its build command copies only `index.html`, `css/` and `js/` into `public/` (the published directory, git-ignored), so a new top-level file or folder the game loads must be added to that `cp` command, or it will 404 in production while working locally.

## Architecture

**No modules.** Each file is a classic `<script>` that declares globals (`Game`, `GameMap`, `Renderer`, `UI`, `Sprites`, `LEVELS`, `WEAPONS`, `TILE`, `U`, etc.). The load order in `index.html` is significant: `util → levels → map → entities → game → sprites → render → ui → main`. A new file must be added there in dependency order.

**Two coordinate scales** (defined in `util.js`):
- `U = 32` px is one ASCII map cell and the unit for gameplay distances (weapon ranges, view range, flash radius are all written as `n * U`).
- `TILE = 16` px is one cell of the fine grid that `GameMap` actually uses. ASCII cell `(x,y)` maps to fine cell `(2x,2y)`, and the in-between fine cells join neighbouring walls. As a result, walls are one fine cell thick and doors are `DOOR_LEN = 3` fine cells wide. The fine grid is `(2·AW−1) × (2·AH−1)`.

**Game / render separation.**
- `Game` (`js/game.js`) owns all simulation state and is the largest file. It covers player input handling, doors (animated `progress`/`target`, with open/ajar/closed states), bullets, flash grenades, enemy AI, teammate AI (follow/hold/move orders, watch spots, formation) and vision polygons (fog of war via `map.explored`). `update(dt)` runs `step(dt)` only when the game is neither over nor paused.
- `Game` emits events through a small `on`/`emit` bus: `'level'`, `'pause'`, `'over'`, `'weapon'`. `Renderer` and `UI` subscribe to these; the game never calls them directly.
- Visual side effects are handed to the renderer through a queue. The game calls `Game.addDecal({type: 'hole'|'blood'|'pool'|'casing'|'scorch', ...})`, which pushes into `game.decals` only if `Game.seesPoint` finds the spot inside a vision polygon; otherwise the decal waits in `game.hiddenDecals` until `computeVision` sees it. `Renderer.draw` then paints the queue once onto a persistent offscreen `decalC` canvas and clears it. Never push to `game.decals` directly, or blood shot through a closed door shows up in the fog. For the same reason, bullets and short-lived `effects` (blood spray, sparks, splinters) are drawn under `Renderer.clipToVision` (a clip to the current vision polygons), flying casings only where seen, and dead enemies and hostages only once `bodySeen` is set.
- The minimap (`Renderer.buildMinimap` / `drawMinimap`, toggled by `game.minimap`) has its own layers: `miniC` (the reduced plan), `miniExpC` (explored mask, filled alongside the fog in `drawFog`) and `miniTmpC`, composited with `source-in` so only explored tiles show. The plan itself comes from the static `Renderer.paintPlan(ctx, map, s, doors)` (floors by `MINI_FLOORS`, walls, props, windows), which `UI.drawPlan` reuses for the plans on the « Missions » screen (with closed doors and a ring on every breach) and for the briefing plan (`opts`: `sel` fills the chosen entry with an inward arrow, `hover`, `threat` rings breaches red in siege, `pad` margin in fine cells, `PLAN_PAD`). In siege, `spawnAssault` stores `siege.arrival = { breach, room, at }` and `drawArrival` flashes that room (masked once into `miniArrC`) plus ripples and an inward arrow on the breach for `ARRIVAL_ALERT` seconds.
- `Renderer` rebuilds its offscreen layers on `'level'`: `staticC` (floors, walls, props, door frames), `decalC`, `fogC` and `exploredC`. Fog is updated incrementally from `map.newlyExplored`.
- `UI` (`js/ui.js`) updates the DOM HUD and overlays (briefing, pause, end screen) defined in `index.html`.

**Input.** `main.js` translates DOM events into `game.input`:
- `keys[code]` is true while a key is held.
- `pressed[code]` is true for a single frame. This includes the synthetic codes `Mouse0`, `Mouse1`, `Mouse2`, `WheelUp` and `WheelDown`. `Game.update` resets `pressed` at the end of each frame.

Bindings use `KeyboardEvent.code`, i.e. physical keys. `KeyW/A/S/D` is therefore ZQSD on AZERTY keyboards, and `KeyQ` (the walk/run toggle) is the physical A key on AZERTY. The actual bindings are in `Game.updatePlayer`:

| Action | Keys |
|---|---|
| Reload | `R` or middle click |
| Weapon | `1` / `2`, or `Alt` to cycle |
| Laser | `L` toggles `player.laserOn` |
| Lamp | `X` toggles `player.lampOn` (the mates' `lampOn` follows) |
| Door | `E` toggles open/closed (picks a locked door); the wheel steps closed ↔ ajar ↔ open |
| Breaching charge | `B` places one on the nearest closed door; `B` again detonates it |
| Shout | `C`: suspects in view may surrender |
| Flash grenade | `Space` or `G` |
| Pick up a weapon | `V` near a body |
| Hostage / cuffs | `H` near a hostage: take charge (follow) / make wait; near a surrendered suspect: cuff (`Game.interact`) |
| Minimap | `M` toggles `game.minimap` |
| Squad | `T` toggles hold/follow; right click orders a move (right click on the player: follow; on a closed door: stack) |
| Walk/run | `Q`/`Shift` toggles |

If the controls change, update the README table, the HUD hints in `index.html` and the help text in `js/ui.js` too.

**Pathfinding and vision** are implemented in `GameMap` (`js/map.js`):
- A* with a `MinHeap`: `findPath`, then `smoothPath`, then `routeTo`.
- DDA-style `castRay` and `hasLOS`.
- Collision via `circleFree`.
- Props block movement but not sight. Closed doors block both. Thrown grenades fly over props: `Game.grenadeBlocked(x, y, overProps)` ignores them while the grenade is airborne (`GRENADE_FLIGHT`) or resting on one (`grenadeOnProp`, it then rolls off), and `clearThrow` only checks props on the rolling part of the throw.
- Props listed in `PROP_AGAINST_WALL` get `rot` (back to the adjacent wall; a row only backs onto the wall running along it) and `link.l` / `link.r` (same prop next to it) from `GameMap.fitProp`; `Sprites.paintProp(ctx, p)` draws them in that local frame (back toward −y) so `sss` reads as one sofa. `breachLabel` names a breach by the façade it pierces, adding a position when two of the same kind share a side.

**Noise** (`js/game.js`): `Game.noise(x, y, R, source, kind)` is the single entry point (shots use `w.noise` cells, set per weapon in `js/entities.js`; doors, breaching, impacts, bodies, grenades, shouts and running footsteps call it too). `soundField` runs a Dijkstra over the fine grid up to `R` (a shared buffer, read it immediately): floor costs its length, walls add `SOUND_WALL`, impassable doors `SOUND_DOOR`, windows `SOUND_GLASS`, void blocks; perceived intensity is `1 − d/R`. `NOISE_KINDS` gives each kind its weight, whether it is `important`, and its on-screen life and colour. Suspects go through `hearNoise`: suspicion accumulates (a burst counts less than distinct noises) and decays by `SUSPICION_DECAY`; above `HEAR_TURN` they turn and keep watching that way (`homeAngle`); an important noise above `HEAR_GO`, or suspicion above `SUSPICION_GO`, makes them want to go, but `noise` only sends `RESPONDERS` per location (closest by ear) unless suspicion passes `SUSPICION_ALL`. `investigate` aims at the noise with an error that grows as it fades; after searching, the `return` state walks back to `e.home`. Allied noises only count for `ALLY_ALARM` kinds (shot, voice, body). A suspect shouts (`voice`) when it spots someone (`enemyCombat`, every 5 s at most) or finds a body (`spotBody`). Operators only update `lastKnown` from what they hear; mates turn their head. For the player, noises heard out of sight become `game.heard` markers (merged by kind and direction, drawn as arcs by `Renderer.drawHeard`), and the player's own noises leave `game.ownNoise` (cells of the field, drawn under the fog by `drawOwnNoise`). Footsteps: `footstep` every `STEP_EVERY` px, radius from `STEP_NOISE` (`stepNoise` for the AI; walking is silent). Suppressors: `SUPPRESSORS` in `js/entities.js` (lower `noise`, heavier, longer, 9 mm on a subsonic load (`subsonic: 'load'`) scaled by `SUBSONIC`, the natively subsonic .45 (`'native'`) and supersonic calibres unchanged, `tint.sup` draws the can). The player's are chosen per weapon (see **Weapons**); `game.loadout.teamSup` suppresses the mates (`makeSlot(key, true)`, dealt from suppressible weapons only), and toggling it in the briefing reloads the level.

**Entities** (`js/entities.js`): the file defines `Agent`, plus `Player`, `Teammate` (configured by `TEAMMATE_DEFS`, including each mate's weapon) and `Enemy`, which extend it; `Hostage` is standalone.

**Fiber optic** (`js/game.js`): holding `F` near a closed or ajar door runs a `fiber` action, then sets `player.fiber = Game.fiberSpot(...)` — a viewpoint just past the leaf. `computeVision` casts an extra 150° / 6 U cone from there (so fog and `sees` include it) and `updatePlayer` blocks firing and reloading while it is out; moving, opening the door or releasing the key clears it. `Sprites.actionPose` keeps the arm extended for the sustained pose via `actStyle`, which synthesises `act: { type: 'fiber', k: 1 }`.

**Two-handed actions** (`js/game.js`): `Game.startAction(agent, type, dur, done)` puts `agent.act = { type, t, dur, done }` on any agent (player, mate or enemy) and cancels a running reload. `Game.updateActions` (called from `step`) advances it, runs `done()` at the end and leaves `agent.handBloom` behind, which `Game.spreadOf` adds to the spread and decays over ~0.6 s; an acting agent also gets a flat 7° penalty, so the crosshair opens visibly. While `agent.act` is set nobody fires or reloads, the player moves at 55 % speed and `moveAlong` keeps the AI still. `Game.doorBlocker(door)` reports what stands in the frame (an agent or a grenade) and is checked both before the closing gesture and on completion, so a refusal is immediate and explains itself; `doorAction` says why any refusal happened, since silence reads as a broken key. Doors have four steps, `DOOR_STEPS = [0, 0.3, 0.6, 1]` in `js/map.js`, and `GameMap.doorPassable` opens the way from `DOOR_PASS` (0.6, « entrouverte ») on, for `circleFree` and for `moveAlong`/`waitDoor`; `Game.doorStep(d, dir)` picks the next one for the wheel, `E` jumps straight to open or closed. A door leaf is a real sight blocker: `GameMap.leafSeg(d)` is the leaf segment and `GameMap.leafBlock` shortens every ray in `castRay` (hence `hasLOS`, the vision polygons, fog and bullets) at the leaf, so a door that is not wide open only lets sight through the gap at the leaf's free end — which is why peeking works from beside the gap and up close, not from across the room. `blocksSight` therefore stops blocking the doorway tiles as soon as the door leaves its closed state. Doors go through `Game.doorAction` (0.25 s of handle work plus 0.3 s per unit of leaf travel, so easing a door ajar is quicker than swinging it wide; ×1.3 for enemies) which only then calls `openDoor`/`closeDoor`; the flash is `throwFlash` (wind-up) → `p.cooking` (the fuse, `FUSE[kind]`, starts when the wind-up ends) → `Game.updateCooking` (called from `step`, so it keeps burning even if the player dies): releasing `Space`/`G` throws it with the burnt time passed as `spawnFlash(..., cooked)` and carried on the grenade as `g.cooked`, while running out detonates it in the player's hand. Firing and reloading are blocked while `p.cooking` is set, and the crosshair ring runs backwards in red. `Sprites.actionPose` animates the gesture from `st.act = { type, k }`, tilting the gun down and reaching with one hand.

**Breaching** (`js/game.js`): a bullet fired from a `kind: 'shotgun'` weapon carries `breach: 1` (not while its shooter is blind-firing, see **Door penetration**); the first door it meets goes through `Game.breachDoor`, which counts pellets (`door.hits`, reset after 3 s without an impact) and at `BREACH_PELLETS` sets `door.broken`, swinging it open. `doorAction` and `closeDoor` refuse to close a broken door, and `drawDoors` replaces its handle with splintered wood.

**Door penetration** (`js/game.js`): `castRay` reports the obstacle it stopped at as `door` (doorway tile or leaf). In `updateBullets` a bullet that hits a door is not consumed: it keeps `w.pierce` of its damage (0.2 for buckshot to 0.7 for 7.62 NATO), deviates by up to 1.6°, resumes 3 px past the impact and raises `pierced`, which caps at two doors; below 2 damage it stops. Walls and props are unchanged. This is symmetric, so enemies shoot through doors too. Suspects also fire *into* doors on purpose: `GameMap.doorsOnLine(x0, y0, x1, y1)` is 0 for a clear line, the number of doors a bullet would cross (at most two), or −1 behind a wall. `Game.startBlindFire(e, x, y)` sets `e.blind = { x, y, t, off }` (state `engage`, `lastKnown` = the point) when only doors stand between; `enemyCombat` calls it when a seen target is lost behind a door, and `doorShotAlarm` (from `updateBullets`, for `pierced` bullets passing within `BLIND_NEAR`) aims it at the bullet's origin `b.ox/b.oy` with half a cell of error. `blindFire` then fires bursts at the point, each shifted by up to `BLIND_SWEEP`, for `BLIND_FIRE` s or until the line is clear or walled; `updateEnemy` keeps the suspect in place meanwhile, after which `engage` → `investigate` sends it to look. Operators never fire blind (hostages may be behind).

**Relay and dropped weapons** (`js/game.js`): when the player dies and a mate is alive, `step` waits `RELAY_DELAY` then calls `Game.takeOver`, which turns the nearest living mate into the player *in place* — `Object.setPrototypeOf(m, Player.prototype)` after deleting its own `slot` (it would shadow `Player`'s getter) — so enemy targets stay valid. The old player object moves into `mates` as a dead entry, which the squad HUD shows as down. `checkEnd` loses only when no op is alive. Every body keeps its weapon in `slot` (or `slots[cur]` for a former player); `Game.pickUp` (`V`, a 0.5 s `pickup` action) swaps it with the player's slot of the same category (pistol vs primary), and `Game.pickupSlot` converts AI weapons through their `pickup` key (`ak` → `akP`, `hk416op` → `hk416`, ...) and replaces infinite ammo with the real magazine and reserve. A body with no weapon has `slot === null`, so `Agent.weapon` and `gunStyle` accept null.

**Hostages** (`js/game.js`): `Hostage.radius` is a getter, 7 kneeling and 9 standing (`h.standing`: escorted and not ducking, or exiting). In `Game.damage` a first hit below `HOSTAGE_GRAVE` only sets `h.wounded` (drawn by `Sprites.hostage` / `hostageStanding`); a second hit, or one at `HOSTAGE_GRAVE` or more, kills.

A hostage is only saved once out of the building. Only `Game.rescueTeam` escorts (`'ops'` in assault, `'enemy'` in siege): the player with `H` (`toggleEscort`, a 0.5 s `hostage` action, then `takeCharge(h, p)`), the siege `Operator`s through `takeHostage` / `escortToExit` (nearest exit by path length, `nearestExit`; the operator opens a closed exterior door, waits for a lagging hostage and walks back to one that has no path). `Game.updateHostages` (called from `step`) makes an escorted hostage follow (`followEscort`: A* with `{ passableDoors: true }`, so a hostage never opens a door; rank in the file = how many followers are closer to the escort, gap `HOSTAGE_GAP + rank · HOSTAGE_GAP_STEP`), releases it when the escort dies (`releaseHostage`: it kneels where it is), and starts the exit (`exitFor` → `startExit` → `stepExit` → `evacuate`) when it reaches a usable breach or its escort stands at one in view: an `X` must be `doorPassable`, a `W` is climbed (1.1 s pause on the sill). An exiting hostage carries on even if its escort falls. `fireWeapon` makes escorted hostages within `HOSTAGE_DUCK_RANGE` duck for `HOSTAGE_DUCK` s. `separateHostages` lets standing hostages yield to everyone except kneeling hostages, and `doorBlocker` counts hostages in the frame. Evacuated hostages (`h.evacuated`) stay in `game.hostages` for the counts but are skipped by bullets, frags, `lineOfFireClear`, vision and drawing; the renderer (`hostageShown`) only draws a moving hostage while it is in view.

**Fire discipline** (`js/game.js`): `Game.lineOfFireClear(shooter, target, x, y)` blocks a mate's shot when an ally or hostage is in the axis. A mate that stays blocked past 0.35 s gets `m.blockedLine`, which frees it to move again and sends it to `Game.firingSpot` — the nearest tile with a clear line — instead of standing still. A move order also takes priority over contact, so an engaged mate still obeys. `lineOfFireClear` takes the shooter's own team as friends, so it also serves the siege `Operator`s: `enemyCombat` holds their fire and `updateAssault` sends them to `firingSpot` once blocked. Trained shooters (mates and operators) widen the margin with their current spread; operators go further and also count hostages up to 2.5 U behind the target, because a burst that misses keeps going. `firingSpot` asks for 12 px more clearance than firing does, otherwise a mate walks to a spot and then refuses to shoot from it. Keep these escapes in mind when touching `updateMate`: without them a mate freezes in front of a hostage.

**Surrender and arrest** (`js/game.js`, assault only): `Game.shout` (`C`, `SHOUT_COOLDOWN`) rolls `surrenderChance(e)` for every suspect the player sees (`playerSees`) within `SHOUT_RANGE` — up when stunned, wounded, taken from behind or covered by mates, down when it is fighting or has an accomplice close by — then makes a `voice` noise. `surrenderTo(e)` sets `e.surrender = { t, lapse }`; `updateEnemy` hands such a suspect to `updateSurrendered` (it kneels, `Sprites.kneeling`, weapon at its feet), `acquireFor` and `mateCombat` never target it, and `noise` / `doorShotAlarm` skip it. Left unseen by every op for `SURRENDER_LAPSE` it picks its weapon back up. `Game.interact` (`H`) cuffs the nearest one (`cuff`, `CUFF_TIME`) before looking for a hostage; `e.cuffed` counts as neutralised: `Game.active(e)` is `alive && !cuffed`, and `checkEnd` wins when no suspect is active. `stats.arrests`, `stats.badKills` (killed while surrendered) and `stats.friendly` (op hit by an op) feed the end score.

**End score** (`js/game.js`): when `checkEnd` ends the mission it stores `game.score = scoreReport(result)` (lines `{ label, detail, pts }`, `total` out of 100, `grade` S/A/B/C/D, a lost mission capped at 49 and D) and, while `game.saveRecords` holds, `saveRecord` keeps the best total under `breach.best.<mode>.<level>` (`game.record = { prev, beaten }`). `UI.showEnd` draws it above the stats.

**Darkness and lamps** (`js/game.js`): `loadout.cutPower` (assault, briefing toggle `#ovPower`, reloads the level like `teamSup`) sets `game.dark`. In the dark `computeVision` casts the player's and mates' cones to `DARK_SIGHT` and `lampPoly` adds a `lamp: true` polygon (`LAMP_HALF`, `LAMP_RANGE`) for each lit lamp; `canSee` falls back to `DARK_SIGHT` unless `sightOf` finds the target lit — carrying a lit lamp (`lampLit`), inside a beam (`inLamp`) or `glowT > 0` (set by `fireWeapon` for unsuppressed shots, `SHOT_GLOW`). The lamp is an accessory like the laser (`LIGHTS` in `js/entities.js`, `acc.light`, `tint.light`); in the dark the mates get one (`acc: { sup, light }`) and mirror the player's `lampOn`. `dazzles(src, e)` adds `LAMP_DAZZLE` to a suspect's reaction when it acquires someone shining a lamp in its face. `Renderer.drawLamps` (warm cone), `drawDark` (`darkC`, a veil holed by beams, muzzle glow and blasts) and `drawGlimpsed` (suspects seen by their muzzle flash, drawn over the fog) render it.

**Locks and charges** (`js/game.js`, assault): `loadLevel` locks each door with `LOCK_CHANCE` while `game.lockDoors` holds (`d.locked`). `doorAction` on a locked door by an op runs a `lockpick` action (`LOCKPICK_TIME`, sets `d.lockKnown`, drawn as a red lock): the player only unlocks, a mate unlocks and opens; suspects have the key (a little slower). `breachDoor` and charges clear `locked`. `Game.chargeKey` (`B`): with no charge placed, a `charge` action (`CHARGE_PLACE`) pushes `{ door, side, x, y, t }` into `game.charges` (`player.charges`, `CHARGES`); with one placed, `detonateCharge` breaks the door open and stuns (and close up wounds) everything within `CHARGE_RADIUS` on the far side, wounding anyone within 1.4 U on the near side. `updateCharges` drops a charge whose door gets opened.

**Patrols and general alarm** (`js/game.js`, assault): while `game.patrols` holds, `loadLevel` calls `buildPatrols`, which gives `PATROLS` random suspects `e.patrol = { pts, i, wait, going }`: their post plus one or two points, each leg `PATROL_LEG` of path, none through the entry room. In the `idle` state `updateEnemy` hands them to `patrolStep` (walk at `PATROL_SPEED` in `moveAlong`, pause `PATROL_PAUSE` looking around, next point); `e.home` follows the route, so `return` after an investigation brings them back onto it. While `game.alarms` holds, a suspect that acquires an op starts `e.spotT` (`enemyCombat`); `updateEnemy` advances it except while stunned, and at `ALARM_TIME` calls `raiseAlarm`: `game.alarm = { by, x, y, t }` (once per mission), every other active suspect gets `alerted`, `reaction × ALARM_REACT`, turns toward the spot, and the `RESPONDERS` closest investigate it. `drawEnemy` shows the countdown as a red « ! » ring; the HUD objective line and the end score (−5) show the alarm.

**Coordinated entry** (`js/game.js`): a right click released on a closed door (`doorAtPoint`) calls `orderStack(d)`: mates get `order = 'stack'` and an `orderPos` on each side of the frame, on the player's side (`stackSpot`, `m.stackSide`), facing the door; `game.stack = { door, side, ready, wait }`. `updateStack` (from `step`) waits until the door is passable or broken, then `ENTRY_DELAY` (longer while an ops flash is cooking or live), and `launchEntry` turns them into `move` orders to the room corner on their side with a `coverAngle` toward the back of the room. In `updateMate`, `stack` moves like `move` but never opens doors and never turns into `hold`; any other order clears `game.stack`.

**Teammate orders** (`js/game.js`): `Game.orderFollow`, `Game.orderMove(wx, wy, coverAngle)` and `Game.toggleHold` set `m.order` (`follow` | `hold` | `move`). A held right click builds `game.orderDrag` in `Game.updatePlayer`; on release, the dragged angle is passed as `coverAngle` and stored on the one mate placed on that side as `m.coverAngle`. `Game.pickWatch` returns that angle unchanged instead of scoring watch candidates, and no scan sweep is started while it is set. Any new order clears it.

**Weapons** are real firearms, defined in the `WEAPONS` table in `js/entities.js`:
- Display data (`name`, `maker`, `caliber`, `mode`, `rpm`, `weight`, `note`) follows manufacturer specs. `rof` is derived from `rpm`, and `mobility` (a player speed multiplier) from `weight`. Keep new weapons consistent with real data.
- Tuning fields (spread, bloom, range falloff, `pellets`) are combined by `Game.spreadOf` and `Game.fireWeapon`. Enemy weapons (`ak`, `pistolE`) have `mag: Infinity` and burst/pause.
- `kind` selects the drawing in `Sprites.gun` (`rifle`, `smg`, `pdw`, `shotgun`, `pistol`, `ak`); `tint` selects a colour/shape variant; `snd` sets the shot sound.
- `reloadType: 'shell'` loads one shell per `reload` seconds, and firing interrupts it.
- Nobody is armed the same: `dealWeapons(pool, n)` (in `js/entities.js`) draws without repeats from `MATE_POOL`, `SIEGE_MATE_POOL` or `OPERATOR_POOL`; `loadLevel` deals the mates' weapons and `spawnAssault` the operators'. Suspects pick at random from the mission's `enemyWeapons`.
- Reloading animates: `reloadT` is paired with `reloadDur` wherever it is set (`startReload`, `Game.mateReload`), and `actStyle` synthesises `act: { type: 'reload' }` so `Sprites.actionPose` plays the magazine change (`st.mag` is the magazine in hand). `mateReload` scales the duration for `reloadType: 'shell'`.
- `PRIMARY_WEAPONS` and `SIDEARMS` list what the briefing screen offers. The player's choice is `game.loadout` = `{ primary, sidearm, shield, acc, teamSup, cutPower, vest }`, stored in `localStorage` under `breach.loadout.<mode>`, completed by `Game.normLoadout` (which also turns an old team-wide `sup` flag into per-weapon suppressors) and applied via `Game.setLoadout` → `Player.equip`.
- Accessories are per weapon: `loadout.acc[key] = { sup, laser, light, grip, mag }`, set from the briefing by `Game.setAccessory`. `fittedDef(key, acc)` returns the cached fitted variant (`suppressedDef(key)` is the suppressor-only one), ignoring what the weapon cannot take (`SUPPRESSORS`, `LASERS`, `LIGHTS`, `GRIPS`, `MAGS`); `makeSlot(key, acc)` builds a slot from it. The foregrip scales `bloom`, `bloomMax` and `recoil` by `GRIP` (`tint.grip`); the extended magazine sets `mag` and multiplies `reload` from `MAGS`, reserve unchanged (`tint.extMag`: a length ratio, `'drum'` or `'tube'`, drawn by the `mag` helper in `Sprites.gun`). A laser (`w.laser`, `tint.laser` draws the module, `LASER_MOUNT` in `js/sprites.js`) multiplies the movement spread by `LASER_MOVE` in `Game.spreadOf` while `Game.laserLit` holds (on, and the gun not lowered by an action, reload, fiber or cooking). `Game.laserBeam` is the beam (muzzle to the first sight blocker or person); `step` keeps it in `game.beam`, and `Game.spotLaser` (from `updateEnemy` and `updateAssault`) lets an idle suspect who sees a point of it turn toward the source and, above `SUSPICION_GO`, investigate. `Renderer.drawLaser` draws it under the vision clip.
- Vests: `VESTS` in `js/entities.js` (`loadout.vest`, assault only, `MODES[mode].vests`, default `vestL`; `normLoadout` fills it in), toggled by `#ovVest` in the briefing. `Player.equip` sets `player.vest`; `updatePlayer` scales speed by `vest.mobility`; `Game.vestHit(c, b, ang, dmg)` (bullets in `updateBullets`, and what passes through a shield in `shieldHit`) leaves `blunt` of the damage when `b.pen ≤ vest.soft`, or `plateBlunt` within ±`arc` front or back when `b.pen ≤ vest.plate`. Only the player wears one; `st.plates` draws the heavy one.
- Shields: `SHIELDS` in `js/entities.js`, chosen instead of the primary (`loadout.shield`, assault only, `MODES[mode].shields`). `Player.equip` then keeps only the sidearm (plus `SHIELD_EXTRA_MAGS`) and narrows `fov`; `updatePlayer` scales speed by `shield.mobility`, `spreadOf` multiplies by `shield.aim` (half the penalty with a laser), and `nearestDrop` only offers pistols. In `updateBullets` a carrier has an arc of ±`shield.arc` at `SHIELD_REACH` in front of the body circle; a bullet entering it goes to `Game.shieldHit`, which stops it if its `pen` (penetration class from the weapon: 1 handgun/9 mm/buckshot, 2 for `mp7`/`tt33`, 3 rifle) is at most `shield.stops`, else deals `through` of the damage. `Sprites.shieldHeld` draws it on the arm (`shieldStyle` in `js/render.js`), `Sprites.shieldFlat` dropped by a body and on the briefing card.
- The briefing icons (`UI.drawWeapon`) reuse `Sprites.gun` at one shared scale, so relative sizes match the in-game drawings.
- The briefing (`UI.showBriefing`) must fit one screen without scrolling: three columns, left the plan and the entry (click a breach on `#ovPlan`, or its button), middle the weapon cards (`CARD_SCALE`), the accessory rows (`#waccs`, always two rows of five buttons under the weapon name, greyed for a shield) and one line with the vest and teammates' suppressor toggles, right the two spec sheets (`#wdetail`). The sheets never move when the choice changes: `.brief-specs-in` is absolutely positioned so they take the height of the other columns, half each, and every sheet built by `UI.fiche` has the same skeleton (one-line head, bars on 7 fixed rows, 8 specs, then text that scrolls on its own). Keep that skeleton when adding a field. The key list lives in the help screen (`Commandes` button, `showHelp(back)`).

## Tests

`tests/index.html` loads the game scripts plus `tests/tests.js`, runs every scenario synchronously on a hidden canvas and HUD, and sets `document.title` to `PASS` or `FAIL n`. Headless: `chrome --headless --allow-file-access-from-files --dump-dom tests/index.html`. `mkGame(opts)` builds a game (`mode`, `level`, `loadout`, `entry`); `checkEnd` is stubbed by default because a finished mission freezes `update`, `alone: true` removes enemies and mates so the player is not shot mid-measurement, and `noEnemyAI` freezes suspects. `mkGame` also pins `entryRandom = false`, since the entry is otherwise random, turns off random locks (`lockDoors`, unless `locks: true`), patrols (`patrols`, unless `patrols: true`), the general alarm (`alarms`, unless `alarm: true`) and score records (`saveRecords`). Tests never call `setMode`/`setLoadout`, and the one that exercises `setEntry` saves and restores `breach.entry`, so they leave `localStorage` as they found it. Add a scenario for every behaviour fix.

## Breaches (entries from outside)

`X` (exterior door) and `W` (window) sit in the outer wall. `GameMap.addBreach` records each one in `map.breaches` with its `inside` point (the walkable tile on the building side) and inward `angle`; `breachLabel(b)` names it by compass side. An `X` is a normal door; a `W` is `map.windows` / `windowAt`: floor tiles (so sight and bullets pass) that `blocksMove` refuses, so nobody walks through. The outside is void, so nobody can leave. In assault mode the player starts at `breaches[game.entryIndex]`, drawn at random on every load while `game.entryRandom` holds (the default, saved under `breach.entry` and set from the briefing through `Game.setEntry(i | null)`), one map cell inside (`Game.entryStart`, so mates are not pinned against the façade). The entry zone is empty: `GameMap.roomOf(x, y)` flood-fills the room (stopping at walls, doors and windows) and `Game.clearEntryZone` moves any enemy or hostage found there to the nearest free tile outside it. The maps already respect this; the guard is a safety net; in siege mode `spawnAssault` rotates waves across breaches and gives each operator an entry gesture (the door opening, or 1.3 s to climb through a window).

## Game modes

`game.mode` is `'assault'` (the original) or `'siege'`, saved in `localStorage` under `breach.mode` and switched from the briefing via `Game.setMode`, which reloads the level. `MODES` in `js/entities.js` holds each mode's weapon lists and default loadout (the siege side fields `akP`, `ak74P`, `uziP`, `skorpionP`, `m870`, `makarovP`, `tt33`, `glock17`), and loadouts are stored per mode (`breach.loadout.<mode>`).

Every map has 9 enemy spawns and 3 to 5 hostages (3, 4 and 5 on the first three maps, 4, 4 and 5 on Hôtel, Banque and Centre de données) — those counts are what `loadLevel` spawns; keep them when editing maps. The positions themselves are drawn per game by `Game.buildPosts`, which shuffles the map's own spawns together with a grid of free tiles, keeps them 2 U apart (1.2 U if a map is cramped) and skips the assault entry room. In siege the player takes the first drawn post, so the leader moves around too. In siege mode the mates take no orders: `Game.canCommand` refuses `T`, the right click and every `order*` call, so each militant holds its post.

In siege mode `loadLevel` reassigns the roles without touching the engine's notion of sides: the player and `mates` (from `SIEGE_MATE_DEFS`, militant styles, `ak`/`pistolE`) stay team `ops` and start on the enemy spawns, while `enemies` becomes the assault team — `Operator` instances spawned at the map entry with `hk416op`/`mp5op`. Everything that keys off `ops` (vision, fog, friendly fire, orders, HUD squad) therefore works unchanged.

`Game.startSiege` builds `game.siege` (prep timer, `waves` copied from `SIEGE_WAVES` at the top of `js/game.js` — one entry per wave, its size — plus breaches and sector list) and reveals the whole map as explored, since the defender knows the building; the first wave only enters when the prep timer runs out. `Game.updateAssault` replaces `updateEnemy` for those operators: it reuses `enemyCombat`, throws a flash through `maybeFlash`/`spawnFlash` when it knows where the threat was, and walks to a found hostage, else the last noise heard, else the next sector from `Game.buildSectors`. `updateHostageRescue` marks a hostage `found` when an operator sees it; `assaultGoal` sends operators to found hostages nobody escorts yet, and the first one to reach a hostage escorts it out (see **Hostages**). `updateSiege` sends the next wave `gap` (6 s) after the current one is wiped out, or `maxGap` (30 s) after it entered if it still holds; the UI texts read the wave count from `SIEGE_WAVES`. Grenades: `Game.armGrenades` gives the assault side flashes (`p.nade = 'flash'`) and the siege side two frags (`'frag'`, same `flashbangs` counter); a grenade carries `kind`, `team` and `thrower`. `detonateFrag` damages everyone in `FRAG_RADIUS` with line of sight (so walls and closed doors protect), thrower and hostages included. `detonateFlash` spares the thrower's team (they look away) beyond 1.2 U. `maybeFlash` only throws when `Game.clearThrow` finds a free trajectory (no wall, prop or non-open door) and no operator stands near the aim point. The siege side has no fiber optic. `separate` pushes apart agents that sit exactly on top of each other, and `spawnAssault` never places two operators on the same point. The end screen counts losses over the whole group: `game.squadSize` (player + mates, set in `loadLevel`) against the dead in `game.ops`. `checkEnd` branches per mode: in siege you win once the last wave has entered and no operator is alive, and lose if you die or no hostage is left alive in your hands (all dead, or dead and evacuated); a single hostage death only announces how many remain. In assault, `checkEnd` wins as soon as every suspect is down, whether or not the hostages are out (a dead hostage still loses first); `objectiveCues` announces once that all hostages are out while suspects remain. `Game.noise` also turns mates toward nearby noise without moving them.

## Adding a mission

Append an entry to `LEVELS` in `js/levels.js` with the fields `{ name, briefing, enemyWeapons, map }`. The map legend is at the top of that file and in the README:
- `#` wall, `D` closed door, `S` player spawn (fallback when a map has no breach), `H` hostage.
- `X` exterior door, `W` window: entry points from outside. Give every map several, including at least one of each, and keep enemies and hostages out of every room a breach opens into (the tests check it).
- `E` enemy with a random facing; `^ v < >` enemy with a fixed facing.
- Floors: `. , : ; = %` (concrete, parquet, tiles, carpet, marble, diamond plate). A new floor needs an entry in `FLOOR`, a painter in `Sprites.paintFloor` and a colour in `MINI_FLOORS`.
- Props: `c B T p b k` plus `s r a R P C` (sofa, shelving, locker, server rack, pallet, counter). A new prop needs `PROPS`, a case in `Sprites.paintProp`, and `PROP_AGAINST_WALL` if it has a back.
- A lone `#` inside a room is a pillar.
- A space is outside the building.

Keep spawns clear of furniture (a spawn needs `circleFree(12)`) and leave at least two map rows between rows of racks or shelves: with a single map row the aisle is 32 px wide and agents (radius 11) barely fit.

An assault mission is won as soon as every enemy is dead or cuffed; escorting hostages out is optional (it keeps them safe). It is lost if the whole team is down (the player's death alone hands control to a mate) or any hostage dies (in siege mode, only once no hostage is left alive in the player's hands).
