# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Breach Team is a real-time, top-down tactical shooter (a player plus AI teammates) written in plain HTML5 Canvas and vanilla JS. It has no dependencies, no build step, no package manager and no linter; its regression suite runs in a browser (see **Tests**). All graphics (`js/sprites.js`) and sounds (`Sound` in `js/util.js`) are generated procedurally; there are no asset files. The UI text, code comments and the README are in French, so keep new player-facing strings and comments in French.

## Running

Open `index.html` directly, or serve the folder:

```
python -m http.server 8000
```

Then go to http://localhost:8000. Append `#nobrief` to the URL to skip the start screens (mode, map, briefing) and play the first map of the saved mode; this is useful when iterating. Run the regression suite with `bash tests/run.sh` (headless Chrome; `bash tests/run.sh porte` runs only the tests whose name contains « porte », much faster while iterating) or by opening `tests/index.html` (see **Tests** below), then check the change by playing in the browser.

The game is deployed on Render as a static site from `render.yaml`. Its build command copies only `index.html`, `css/` and `js/` into `public/` (the published directory, git-ignored), so a new top-level file or folder the game loads must be added to that `cp` command, or it will 404 in production while working locally.

## Architecture

**No modules.** Each file is a classic `<script>` that declares globals (`Game`, `GameMap`, `Renderer`, `UI`, `Sprites`, `LEVELS`, `WEAPONS`, `TILE`, `U`, etc.). The load order in `index.html` is significant: `util → levels → map → entities → game → game-* → sprites → render → ui → main`. A new file must be added there (and in `tests/index.html`, and `tests/sim.html` for a game file) in dependency order.

**`Game` is split by theme.** `js/game.js` holds the class itself (constructor, settings, `loadLevel`, posts and zones, the loop `update`/`step`, sight helpers, `checkEnd`, the score, vision) and defines `mixGame(part)`; every `js/game-*.js` file declares its constants, then `mixGame(class { ...methods... })`, which copies the anonymous class's methods, getters and statics onto `Game` (a name defined twice throws). The files: `game-combat.js` (fire, bullets, shields, vests, `damage`, grenades, hurt markers, kill feed), `game-noise.js` (noise, hearing, what the player hears, voices, footsteps), `game-doors.js` (two-handed actions, doors, charges), `game-player.js` (player input, weapons and reload, grenades in hand, relay, pickups, summons and cuffs, fiber), `game-menu.js` (the `E` context menu, strategy door buttons), `game-mates.js` (orders, coordinated entry, formation, watch, fire discipline, mate combat), `game-enemies.js` (suspect AI, patrols, alarm, blind fire, `moveAlong`), `game-hunters.js` (autonomous agents), `game-hostages.js` (hostages and escort), `game-siege.js`, `game-squads.js` (trinômes, total war, strategy assault armies), `game-strategy.js`. Constants are globals, so any file may use another's at runtime; only a top-level initialiser must not read a constant declared in a later file.

**Two coordinate scales** (defined in `util.js`):
- `U = 32` px is one ASCII map cell and the unit for gameplay distances (weapon ranges, view range, flash radius are all written as `n * U`).
- `TILE = 16` px is one cell of the fine grid that `GameMap` actually uses. ASCII cell `(x,y)` maps to fine cell `(2x,2y)`, and the in-between fine cells join neighbouring walls. As a result, walls are one fine cell thick and doors are `DOOR_LEN = 3` fine cells wide. The fine grid is `(2·AW−1) × (2·AH−1)`.

**Game / render separation.**
- `Game` (`js/game.js` and `js/game-*.js`) owns all simulation state. It covers player input handling, doors (animated `progress`/`target`, with open/ajar/closed states), bullets, flash grenades, enemy AI, teammate AI (follow/hold/move orders, watch spots, formation) and vision polygons (fog of war via `map.explored`). `update(dt)` runs `step(dt)` only when the game is neither over nor paused.
- `Game` emits events through a small `on`/`emit` bus: `'level'`, `'pause'`, `'over'`, `'weapon'`. `Renderer` and `UI` subscribe to these; the game never calls them directly.
- Visual side effects are handed to the renderer through a queue. The game calls `Game.addDecal({type: 'hole'|'blood'|'pool'|'casing'|'scorch', ...})`, which pushes into `game.decals` only if `Game.seesPoint` finds the spot inside a vision polygon; otherwise the decal waits in `game.hiddenDecals` until `computeVision` sees it. `Renderer.draw` then paints the queue once onto a persistent offscreen `decalC` canvas and clears it. Never push to `game.decals` directly, or blood shot through a closed door shows up in the fog. For the same reason, bullet tracers (`game.tracers`, see **Weapons**) and short-lived `effects` (blood spray, sparks, splinters) are drawn under `Renderer.clipToVision` (a clip to the current vision polygons), flying casings only where seen, and dead enemies and hostages only once `bodySeen` is set.
- The minimap (`Renderer.buildMinimap` / `drawMinimap`, toggled by `game.minimap`) has its own layers: `miniC` (the reduced plan), `miniExpC` (explored mask, filled alongside the fog in `drawFog`) and `miniTmpC`, composited with `source-in` so only explored tiles show. The plan itself comes from the static `Renderer.paintPlan(ctx, map, s, doors)` (floors by `MINI_FLOORS`, walls, props, windows), which `UI.drawPlan` reuses for the plans on the « Missions » screen (with closed doors and a ring on every breach) and for the briefing plan (`opts`: `sel` fills the chosen entry with an inward arrow, `hover`, `threat` rings breaches red in siege, `pad` margin in fine cells, `PLAN_PAD`). In siege, `spawnAssault` stores `siege.arrival = { breach, room, at }` and `drawArrival` flashes that room (masked once into `miniArrC`) plus ripples and an inward arrow on the breach for `ARRIVAL_ALERT` seconds.
- Framing (`Renderer.resize` / `updateCamera`): the zoom follows the window width but never shows less than `VIEW_HALF` (7 U) above and below the screen centre, and the camera leads toward the cursor by `LOOK_AHEAD` of the player–aim gap, capped at `LOOK_MAX` of the smaller half-dimension on both axes, so aiming toward the edge shows about 10.5 U ahead. It pairs with `AI_FIRE_RANGE` (9 U, `Game.fireRange`): every AI shooter (`enemyCombat`, `mateCombat`, `firingSpot`) opens fire only within it, whatever its weapon's range and view range, and closes in otherwise — so nobody is shot from off-screen. Keep the two consistent if either changes. The one exception is an AI weapon with a scope (only the marksman of a strategy precision group carries one): `fireRange` gives it `range × scopeOf(w).reach` up to `AI_SCOPE_RANGE` (16 U), or `AI_SNIPER_RANGE` (24 U) for a precision rifle, since strategy has no on-foot player.
- `Renderer` rebuilds its offscreen layers on `'level'`: `staticC` (floors, walls, props, door frames), `decalC`, `fogC` and `exploredC`. Fog is updated incrementally from `map.newlyExplored`. Each frame only the on-screen part of these map-sized layers is copied and recomposed (`Renderer.viewRect`), and only the vision polygons that meet it (`shownPolys`, `Renderer.polyMeets`) cut the fog and `clipToVision`, so the large battlefields cost no more than a building.
- `UI` (`js/ui.js`) updates the DOM HUD and overlays (briefing, pause, end screen) defined in `index.html`.

**Input.** `main.js` translates DOM events into `game.input`:
- `keys[code]` is true while a key is held.
- `pressed[code]` is true for a single frame. This includes the synthetic codes `Mouse0`, `Mouse1` (middle click: reload), `Mouse2`, the releases `Mouse0Up`, `Mouse2Up`, and `WheelUp` and `WheelDown`. `Game.update` resets `pressed` at the end of each frame.
- In strategy, `mouse.item` is the door button under the drawn cursor (`Renderer.menuItemAt()`: `{ door, id }` or null) and `mouse.ui` is true over the sidebar (`UI.panelHit`), both set by `main.js` each frame like `mouse.ppx` and `mouse.mini`.
- The mouse is pointer-locked on the canvas (a click in game locks it, an open overlay releases it, losing the lock pauses once even if `Escape` also arrives). `Renderer.pointerMove` moves the drawn cursor `renderer.mouse` by `movementX/Y` while locked (absolute `clientX/Y` otherwise), and `inp.mouse` is `Renderer.aimWorld()` each frame.

Bindings use `KeyboardEvent.code`, i.e. physical keys. `KeyW/A/S/D` is therefore ZQSD on AZERTY keyboards, and `KeyQ` (the walk/run toggle) is the physical A key on AZERTY. The actual bindings are in `Game.updatePlayer`:

| Action | Keys |
|---|---|
| Context menu | `E` opens it, the wheel picks a line, `E` validates (see **Context menu**) |
| Reload | `R` or middle click |
| Weapon | `1` / `2`, or `Alt` to cycle |
| Laser | `L` toggles `player.laserOn` |
| Lamp | `X` toggles `player.lampOn` (the mates' `lampOn` follows) |
| Door | `E`, `E` toggles open/closed (picks a locked door); `E`, wheel, `E` for the other steps |
| Breaching charge | `B` places one on the nearest closed door; `B` again (or `E`, `E` from anywhere) detonates it |

| Grenade | `Space` or `G` |
| Switch grenade | `N`: flash ↔ frag (`Game.cycleNade`, police mixed kit) |

If the controls change, update the README table, the HUD hints in `index.html`, the help text in `js/ui.js`, the menu lines' key hints and the strategy commands (`stratCommands`, `UI.commandList`) too.

**Context menu** (`js/game-menu.js`, the `E` menu): `updateMenu` (first thing in `updatePlayer`) takes `E` and the wheel before anything else. `E` calls `Game.openMenu()`, which sets `game.menu = { kind, door, mate, st, near, body, sel, title, items }` for `menuContext()`: your stack waiting for orders, wherever you are (`'stack'`, `stackWaits`; `near` is the door within reach, if any), else your team's placed charge, wherever it is (`'charge'`, `ownCharge`: the detonation first, then `near`'s `doorSection`), else a door within `MENU_REACH` (`'door'`), the nearest crew mate within reach (`'mate'`), or a body still holding a weapon (`'drop'`, `dropsNear`); nothing in reach says so. `menuItems` fills `title` and `items` (`{ id, label, key, off, run }`, or a section header `{ sep: true, label }`) through `stackMenu` / `doorMenu` / `mateMenu`, then `dropMenu` (the `MENU_DROPS` nearest weapons on the ground, `pick0`… → `pickUp(p, body)`); under the stack, `near` adds the fiber (`fiberLine`) when it is the stack's own door, or that door's whole `doorMenu` with ids prefixed `door:`. `key` is a shortcut shown on the line, `off` the reason it is greyed out, and the list is rebuilt every frame while open. On foot the first line is always `cancel` (« Annuler », not in strategy); the next is the simplest action, selected on opening even when greyed (`E`, `E` always tries it and says why it cannot): for a door, open (or close an open one), then the other steps, the fiber, the charge, the crew's stack; for a locked door, pick. The wheel moves `sel` over the lines that are neither greyed nor headers, `E` runs the selected one (`menuPick`: a greyed line only says why); the menu closes once its context is gone (`MENU_KEEP`), and on `setPaused`, `takeOver`, `loadLevel` and the player's death. A double right click (two presses within `DOUBLE_RIGHT` s and `DOUBLE_RIGHT_GAP`) opens the same kind of menu for a point instead (`openZoneMenu(x, y)`, `kind: 'zone'`, `mn.at`, kept open whatever the distance): throw a flash or frag there yourself (`throwAt(p, kind, at)`, through `throwFlash(p, at)`), have the crew mate with a free trajectory do it (`zoneThrower`, `mateThrowAt`), or send the crew (`orderMove`); `zoneDanger` greys a frag near your own or a hostage, `ZONE_THROW` is the throw range. So a single right click's order waits: `updatePlayer` keeps it in `game.rightClick = { t, x, y, o }` and `rightOrder(o)` runs it once `DOUBLE_RIGHT` has passed (a dragged cover direction goes at once); tests step `RIGHT_WAIT` frames after a right click. The player keeps aiming, but any other key pressed while it is open (outside `MENU_KEYS`) only closes it (`closeMenu`) and is swallowed: a click does not fire (`fireLock` until released, as after the click that removes a sticky fiber), a right click gives no order, `M` does not fold the minimap. The actions reuse the key handlers, some split so they take a target: `startFiber(p, d, sticky)` (a sticky fiber stays without `F` held, until a step, a click or `F`), `placeChargeOn(p, d)`. `Renderer.drawMenu(mn, hint)` draws it in screen space beside its target (the door or the mate, flipped near the edges and clear of the strategy sidebar, `panelW`), highlights `sel` and adds the « Molette : choisir · E : valider » foot; `drawMenuTarget` frames the door or rings the mate (or the body); section headers are drawn as small grey titles. In strategy the same `stackMenu` lines become clickable buttons on each door where one of your selected trinômes waits in a stack (`stratDoorMenus`, rebuilt each frame into `strat.menus`; an unselected group shows none): `drawMenu(mn)` highlights the line under the cursor, keeps every line rect in `menuRects`, and `updateCommander` runs the one in `mouse.item` on a left click.

**Pathfinding and vision** are implemented in `GameMap` (`js/map.js`):
- A* with a `MinHeap`: `findPath`, then `smoothPath`, then `routeTo`. `walkField(x, y)` is the Dijkstra version (walking distance to every fine cell, same rules, closed doors passable), used to pick the next sector to sweep.
- DDA-style `castRay` and `hasLOS` (an optional last argument `skip` ignores that door's leaf).
- Collision via `circleFree`.
- Props block movement but not sight. Closed doors block both. Thrown grenades fly over props: `Game.grenadeBlocked(x, y, overProps)` ignores them while the grenade is airborne (`GRENADE_FLIGHT`) or resting on one (`grenadeOnProp`, it then rolls off), and `clearThrow` only checks props on the rolling part of the throw.
- Props listed in `PROP_AGAINST_WALL` get `rot` (back to the adjacent wall; a row only backs onto the wall running along it) and `link.l` / `link.r` (same prop next to it) from `GameMap.fitProp`; `Sprites.paintProp(ctx, p)` draws them in that local frame (back toward −y) so `sss` reads as one sofa. `breachLabel` names a breach by the façade it pierces, adding a position when two of the same kind share a side.

**Noise** (`js/game-noise.js`): `Game.noise(x, y, R, source, kind)` is the single entry point (shots use `w.noise` cells, set per weapon in `js/entities.js`; doors, breaching, impacts, bodies, grenades, shouts and running footsteps call it too). `soundField` runs a Dijkstra over the fine grid up to `R` (a shared buffer, read it immediately): floor costs its length, walls add `SOUND_WALL`, impassable doors `SOUND_DOOR`, windows `SOUND_GLASS`, void blocks; perceived intensity is `1 − d/R`. `NOISE_KINDS` gives each kind its weight, whether it is `important`, and its on-screen life and colour. Suspects go through `hearNoise`: suspicion accumulates (a burst counts less than distinct noises) and decays by `SUSPICION_DECAY`; above `HEAR_TURN` they turn and keep watching that way (`homeAngle`); an important noise above `HEAR_GO`, or suspicion above `SUSPICION_GO`, makes them want to go, but `noise` only sends `RESPONDERS` per location (closest by ear) unless suspicion passes `SUSPICION_ALL`. `investigate` aims at the noise with an error that grows as it fades; after searching, the `return` state walks back to `e.home`. Allied noises only count for `ALLY_ALARM` kinds (shot, voice, body). A suspect shouts (`voice`) when it spots someone (`enemyCombat`, every 5 s at most) or finds a body (`spotBody`). Operators only update `lastKnown` from what they hear; mates turn their head. For the player, noises heard out of sight become `game.heard` markers (merged by kind and direction, drawn as arcs by `Renderer.drawHeard`), and the player's own noises leave `game.ownNoise` (cells of the field, drawn under the fog by `drawOwnNoise`). Footsteps: `footstep` every `STEP_EVERY` px, radius from `STEP_NOISE` (`stepNoise` for the AI; walking is silent). Suppressors: `SUPPRESSORS` in `js/entities.js` (lower `noise`, heavier, longer, 9 mm on a subsonic load (`subsonic: 'load'`) scaled by `SUBSONIC`, the natively subsonic .45 (`'native'`) and supersonic calibres unchanged, `tint.sup` draws the can). The player's are chosen per weapon (see **Weapons**); `game.loadout.teamSup` suppresses the mates (`makeSlot(key, true)`, dealt from suppressible weapons only), and changing it in the briefing reloads the level. The briefing shows it like the vest: two buttons (`UI.teamPicker`, `.teambtn`, the chosen one `.sel`) and below them each mate's dealt weapon (`.teamarms`).

**What the player hears** (`js/game-noise.js`, `Sound` in `js/util.js`): every game sound goes through `Game.sfx(name, x, y, R, ...args)`, which does nothing without an audio context (before the first click, and in the tests) and otherwise calls `Sound[name](...args, o)` with `o = Game.hearAt(x, y, R)`: `{ gain, pan, muffle }`, or null when inaudible. `hearAt` reads the acoustic distance from the listener (`earPos`: the player, or in strategy `game.ear`, the camera centre set by `main.js`) out of `earField`, a `soundField` of radius `EAR_RANGE` around the listener kept in its own buffer (`soundField(x, y, R, st)`) and recomputed when the listener moves `EAR_MOVE` or after `EAR_REFRESH` s; gain is `(1 − d/R)²`, pan follows the screen side, muffle the ratio straight/acoustic distance and the distance itself (`Sound.cut` lowers the cutoffs). Shots are heard `EAR_SPAN` times farther than their AI noise. `Sound` builds everything into a master gain `Sound.out` followed by a `DynamicsCompressorNode`, caches noise buffers by shape (`Sound.buf`, four variants), and offers `noise`, `ring` (band-pass), `tone` plus the sounds: `shot`, `pump`, `reload(cue, w)` (cues from `Game.reloadCues`, played as `reloadT` progresses: `RELOAD_CUES`, one `shell` cue per shell), `draw`, `step(floor)` (`STEP_SOUNDS`, from `footstep`), `impact(mat)` (wall, flesh, and `LOW_COVER` materials), `body`, `cuffs`, doors, grenades, `alarm` (non-spatial on purpose). UI ticks call `Sound.tick` without `o`. Voices: `Game.voice(a, kind, prio)` picks a line from `VOICE_LINES[kind][campOf(a)]`, at most once per `VOICE_GAP` per agent and kind (the player excepted), and `Sound.speak` says it with the browser's speech synthesis, one at a time by priority (player 3, own side 2, others 1), volume from `hearAt`, never panned, never pitch-shifted (that made them robotic). Only natural male French voices speak: `Sound.maleVoices()` keeps the `fr` voices whose name says neural (`VOICE_NATURAL`: Microsoft's « Natural » / « Online », Apple's « Premium » / « Enhanced ») and is a man's first name (`VOICE_MEN`, the API has no gender), France first; each agent keeps one (`a.voiceIdx`). Without one the voices stay silent, and the pause screen's « Voix » button says so (`UI.voiceButton`). `Sound.voices` (localStorage `breach.voices`, that button, `Sound.setVoices`) mutes them. Voices are sound only: what the AI hears still goes through `noise`.

**Hurt markers and kill feed** (`js/game-combat.js`): `damage(target, dmg, shooter, ang, cause)` calls `hurtFrom(ang + π, dmg)` when the player is hit (and `shieldHit` with `blocked`), filling `game.hurt` (`{ a, k, t, blocked }`, aged in `step`, gone after `HURT_LIFE`), drawn by `Renderer.drawHurt` as arcs, a pointer and an edge glow. When `game.squads` holds, every death goes through `feedKill` into `game.feed` (`{ killer, kcol, victim, vcol, by, t, mine, friendly }`; bullets carry `b.wname`, frags and charges pass `'grenade'` / `'charge'`), shown by `UI.updateFeed` in `#killfeed` for `FEED_LIFE` s. Opposing trinômes are named from `FOE_NAMES` (`spawnSquad`, `opts.slot` in total war).

**Low cover** (`js/map.js`, `js/game-combat.js`): props in `LOW_COVER` (`sandbag` `g`, `lowwall` `m`, `car` `V`, with their impact material) block movement but not sight, like any prop, and also bullets: `GameMap.coverShields(x0, y0, x1, y1, reach)` walks from the target toward the shooter, finds the first cover within `COVER_GUARD` of the target, follows it to its shooter-side face, and returns it unless that face is within `reach` (`COVER_REACH`) of the shooter (who then fires over it). `updateBullets` checks it from the bullet's origin `b.ox/b.oy` to the victim: `COVER_STOP` of such bullets end at the cover (`coverHit`: spark, hole, impact noise and sound); one that passes sets `b.overCover`. Frags use `reach` 0 and deal `COVER_FRAG`. Trained shooters (`mateCombat`, hunters in `enemyCombat`) count `coverT` while their target is covered and set `blockedLine` past `COVER_FLANK`, and `firingSpot` refuses spots from which the target stays covered, so they flank. A car is a block of `V` cells (two by four, never touching another car): `GameMap` floods it into `p.car = { x0, y0, w, h, cx, cy, lead }` and only `lead` paints it. The minimap shows cover brighter (`Renderer.paintPlan`).

**Entities** (`js/entities.js`): the file defines `Agent`, plus `Player`, `Teammate` (configured by `TEAMMATE_DEFS`, including each mate's weapon) and `Enemy`, which extend it; `Hostage` is standalone.

**Fiber optic** (`js/game-player.js`): holding `F` near a closed or ajar door runs a `fiber` action, then sets `player.fiber = Game.fiberSpot(...)` — a viewpoint just past the leaf. `computeVision` casts an extra 150° / 6 U cone from there (so fog and `sees` include it) and `updatePlayer` blocks firing and reloading while it is out; moving, opening the door or releasing the key clears it (`endFiber`; one set from the `E` menu is `sticky`: a click or `F` instead of the release). `Sprites.actionPose` keeps the arm extended for the sustained pose via `actStyle`, which synthesises `act: { type: 'fiber', k: 1 }`.

**Two-handed actions** (`js/game-doors.js`): `Game.startAction(agent, type, dur, done)` puts `agent.act = { type, t, dur, done }` on any agent (player, mate or enemy) and cancels a running reload. `Game.updateActions` (called from `step`) advances it, runs `done()` at the end and leaves `agent.handBloom` behind, which `Game.spreadOf` adds to the spread and decays over ~0.6 s; an acting agent also gets a flat 7° penalty, so the crosshair opens visibly. While `agent.act` is set nobody fires or reloads, the player moves at 55 % speed and `moveAlong` keeps the AI still. `Game.doorBlocker(door)` reports what stands in the frame (an agent or a grenade) and is checked both before the closing gesture and on completion, so a refusal is immediate and explains itself; `doorAction` says why any refusal happened, since silence reads as a broken key. Doors have four steps, `DOOR_STEPS = [0, 0.3, 0.6, 1]` in `js/map.js`, and `GameMap.doorPassable` opens the way from `DOOR_PASS` (0.6, « entrouverte ») on, for `circleFree` and for `moveAlong`/`waitDoor`; `Game.doorStep(d, dir)` picks the next one for the wheel, `E` jumps straight to open or closed. A door leaf is a real sight blocker: `GameMap.leafSeg(d)` is the leaf segment and `GameMap.leafBlock` shortens every ray in `castRay` (hence `hasLOS`, the vision polygons, fog and bullets) at the leaf, so a door that is not wide open only lets sight through the gap at the leaf's free end — which is why peeking works from beside the gap and up close, not from across the room. `blocksSight` therefore stops blocking the doorway tiles as soon as the door leaves its closed state. Doors go through `Game.doorAction` (0.25 s of handle work plus 0.3 s per unit of leaf travel, so easing a door ajar is quicker than swinging it wide; ×1.3 for enemies) which only then calls `openDoor`/`closeDoor`; the flash is `throwFlash` (wind-up) → `p.cooking` (the fuse, `FUSE[kind]`, starts when the wind-up ends) → `Game.updateCooking` (called from `step`, so it keeps burning even if the player dies): releasing `Space`/`G` throws it with the burnt time passed as `spawnFlash(..., cooked)` and carried on the grenade as `g.cooked`, while running out detonates it in the player's hand. Firing and reloading are blocked while `p.cooking` is set, and the crosshair ring runs backwards in red. `Sprites.actionPose` animates the gesture from `st.act = { type, k }`, tilting the gun down and reaching with one hand.

**Breaching** (`js/game-doors.js`): a bullet fired from a `kind: 'shotgun'` weapon carries `breach: 1` (not while its shooter is blind-firing, see **Door penetration**); the first door it meets goes through `Game.breachDoor`, which counts pellets (`door.hits`, reset after 3 s without an impact) and at `BREACH_PELLETS` sets `door.broken`, swinging it open. `doorAction` and `closeDoor` refuse to close a broken door, and `drawDoors` replaces its handle with splintered wood.

**Door penetration** (`js/game-combat.js`): `castRay` reports the obstacle it stopped at as `door` (doorway tile or leaf). In `updateBullets` a bullet that hits a door is not consumed: it keeps `w.pierce` of its damage (0.2 for buckshot to 0.7 for 7.62 NATO), deviates by up to 1.6°, resumes 3 px past the impact and raises `pierced`, which caps at two doors; below 2 damage it stops. Walls and props are unchanged. This is symmetric, so enemies shoot through doors too. Suspects also fire *into* doors on purpose: `GameMap.doorsOnLine(x0, y0, x1, y1)` is 0 for a clear line, the number of doors a bullet would cross (at most two), or −1 behind a wall. `Game.startBlindFire(e, x, y)` sets `e.blind = { x, y, t, off }` (state `engage`, `lastKnown` = the point) when only doors stand between; `enemyCombat` calls it when a seen target is lost behind a door, and `doorShotAlarm` (from `updateBullets`, for `pierced` bullets passing within `BLIND_NEAR`) aims it at the bullet's origin `b.ox/b.oy` with half a cell of error. `blindFire` then fires bursts at the point, each shifted by up to `BLIND_SWEEP`, for `BLIND_FIRE` s or until the line is clear or walled; `updateEnemy` keeps the suspect in place meanwhile, after which `engage` → `investigate` sends it to look. Operators never fire blind (hostages may be behind).

**Relay and dropped weapons** (`js/game-player.js`): when the player dies and a mate is alive, `step` waits `RELAY_DELAY` then calls `Game.takeOver`, which turns the nearest living mate into the player *in place* — `Object.setPrototypeOf(m, Player.prototype)` after deleting its own `slot` (it would shadow `Player`'s getter) — so enemy targets stay valid. The old player object moves into `mates` as a dead entry, which the squad HUD shows as down. `checkEnd` loses only when no op is alive. Every body keeps its weapon in `slot` (or `slots[cur]` for a former player); `Game.pickUp` (`V`, a 0.5 s `pickup` action) swaps it with the player's slot of the same category (pistol vs primary), and `Game.pickupSlot` converts AI weapons through their `pickup` key (`ak` → `akP`, `hk416op` → `hk416`, ...) and replaces infinite ammo with the real magazine and reserve. A body with no weapon has `slot === null`, so `Agent.weapon` and `gunStyle` accept null.

**Hostages** (`js/game-hostages.js`): `Hostage.radius` is a getter, 7 kneeling and 9 standing (`h.standing`: escorted and not ducking, or exiting). In `Game.damage` a first hit below `HOSTAGE_GRAVE` only sets `h.wounded` (drawn by `Sprites.hostage` / `hostageStanding`); a second hit, or one at `HOSTAGE_GRAVE` or more, kills.

A hostage is only saved once out of the building (except the escort VIP, see **Escort mode**). Only `Game.rescueTeam` escorts (`'ops'` in assault, `'enemy'` in siege): the player with `H` (`toggleEscort`, a 0.5 s `hostage` action, then `takeCharge(h, p)`), the siege `Operator`s through `takeHostage` / `escortToExit` (nearest exit by path length, `nearestExit`; the operator opens a closed exterior door, waits for a lagging hostage and walks back to one that has no path). `Game.updateHostages` (called from `step`) makes an escorted hostage follow (`followEscort`: A* with `{ passableDoors: true }`, so a hostage never opens a door; rank in the file = how many followers are closer to the escort, gap `HOSTAGE_GAP + rank · HOSTAGE_GAP_STEP`), releases it when the escort dies (`releaseHostage`: it kneels where it is), and starts the exit (`exitFor` → `startExit` → `stepExit` → `evacuate`) when it reaches a usable breach or its escort stands at one in view: an `X` must be `doorPassable`, a `W` is climbed (1.1 s pause on the sill). An exiting hostage carries on even if its escort falls. `fireWeapon` makes escorted hostages within `HOSTAGE_DUCK_RANGE` duck for `HOSTAGE_DUCK` s. `separateHostages` lets standing hostages yield to everyone except kneeling hostages, and `doorBlocker` counts hostages in the frame. When `stepAlong` is blocked (the circle grazes a prop corner, often by a fraction of a pixel), it tries a 1–3 px sidestep that frees the next step before re-pathing. Evacuated hostages (`h.evacuated`) stay in `game.hostages` for the counts but are skipped by bullets, frags, `lineOfFireClear`, vision and drawing; the renderer (`hostageShown`) only draws a moving hostage while it is in view.

**Fire discipline** (`js/game-mates.js`): `Game.lineOfFireClear(shooter, target, x, y)` blocks a mate's shot when an ally or hostage is in the axis. A mate that stays blocked past 0.35 s gets `m.blockedLine`, which frees it to move again and sends it to `Game.firingSpot` — the nearest tile with a clear line — instead of standing still. A move order also takes priority over contact, so an engaged mate still obeys. `lineOfFireClear` takes the shooter's own team as friends, so it also serves the siege `Operator`s: `enemyCombat` holds their fire and `updateAssault` sends them to `firingSpot` once blocked. Trained shooters (mates and operators) widen the margin with their current spread; operators go further and also count hostages up to 2.5 U behind the target, because a burst that misses keeps going. `firingSpot` asks for 12 px more clearance than firing does, otherwise a mate walks to a spot and then refuses to shoot from it. Keep these escapes in mind when touching `updateMate`: without them a mate freezes in front of a hostage.

**Surrender and arrest** (`js/game-player.js`, assault and escort): `Game.shout` (`C`, `SHOUT_COOLDOWN`) rolls `surrenderChance(e)` for every suspect the player sees (`playerSees`) within `SHOUT_RANGE` — up when stunned, wounded, taken from behind or covered by mates, down when it is fighting or has an accomplice close by — then makes a `voice` noise. `surrenderTo(e)` sets `e.surrender = { t, lapse }`; `updateEnemy` hands such a suspect to `updateSurrendered` (it kneels, `Sprites.kneeling`, weapon at its feet), `acquireFor` and `mateCombat` never target it, and `noise` / `doorShotAlarm` skip it. Left unseen by every op for `SURRENDER_LAPSE` it picks its weapon back up. `Game.interact` (`H`) cuffs the nearest one (`cuff`, `CUFF_TIME`) before looking for a hostage; `e.cuffed` counts as neutralised: `Game.active(e)` is `alive && !cuffed`, and `checkEnd` wins when no suspect is active. `stats.arrests`, `stats.badKills` (killed while surrendered) and `stats.friendly` (op hit by an op) feed the end score.

**End score** (`js/game.js`): when `checkEnd` ends the mission it stores `game.score = scoreReport(result)` (lines `{ label, detail, pts }`, `total` out of 100, `grade` S/A/B/C/D, a lost mission capped at 49 and D) and, while `game.saveRecords` holds, `saveRecord` keeps the best total under `breach.best.<mode>.<level>` (`game.record = { prev, beaten }`). `UI.showEnd` draws it above the stats.

**Darkness and lamps** (`js/game.js`): `loadout.cutPower` (assault, briefing pair `.powbtn` « Laissé » / « Coupé » in `UI.powerRow`, reloads the level like `teamSup`) sets `game.dark`. In the dark `computeVision` casts the player's and mates' cones to `DARK_SIGHT` and `lampPoly` adds a `lamp: true` polygon (`LAMP_HALF`, `LAMP_RANGE`) for each lit lamp; `canSee` falls back to `DARK_SIGHT` unless `sightOf` finds the target lit — carrying a lit lamp (`lampLit`), inside a beam (`inLamp`) or `glowT > 0` (set by `fireWeapon` for unsuppressed shots, `SHOT_GLOW`). The lamp is an accessory like the laser (`LIGHTS` in `js/entities.js`, `acc.light`, `tint.light`); in the dark the mates get one (`acc: { sup, light }`) and mirror the player's `lampOn`. `dazzles(src, e)` adds `LAMP_DAZZLE` to a suspect's reaction when it acquires someone shining a lamp in its face. `Renderer.drawLamps` (warm cone), `drawDark` (`darkC`, a veil holed by beams, muzzle glow and blasts) and `drawGlimpsed` (suspects seen by their muzzle flash, drawn over the fog) render it.

**Locks and charges** (`js/game-doors.js`, assault): `loadLevel` locks each door with `LOCK_CHANCE` while `game.lockDoors` holds (`d.locked`). `doorAction` on a locked door by an op runs a `lockpick` action (`LOCKPICK_TIME`, sets `d.lockKnown`, drawn as a red lock): the player only unlocks, a mate unlocks and opens; suspects have the key (a little slower). `breachDoor` and charges clear `locked`. `Game.chargeKey` (`B`): with no charge of the player's team placed, a `charge` action (`CHARGE_PLACE`) calls `placeCharge(a, d, side)`, which pushes `{ door, side, x, y, t, by, team }` into `game.charges` and decrements `a.charges` (`player.charges`, `CHARGES`; the siege operators use it too); with one placed, `detonateCharge` breaks the door open and stuns (and close up wounds) everything within `CHARGE_RADIUS` on the far side, wounding anyone within `CHARGE_NEAR` on the near side, damage and noise credited to `c.by`. Exposure is `blastReaches(d, a)`: line of sight from three points across the doorway's face on the agent's side, ignoring the blown leaf (`hasLOS(..., skip)`), so people flat against the wall beside the frame or behind the swung leaf are reached too. `updateCharges` drops a charge whose door gets opened (and only says so for the player's own). `Renderer.drawCharges` shows the other side's charges only where seen.

**Patrols and general alarm** (`js/game-enemies.js`, assault): while `game.patrols` holds, `loadLevel` calls `buildPatrols`, which gives `PATROLS` random suspects `e.patrol = { pts, i, wait, going }`: their post plus one or two points, each leg `PATROL_LEG` of path, none through the entry room. In the `idle` state `updateEnemy` hands them to `patrolStep` (walk at `PATROL_SPEED` in `moveAlong`, pause `PATROL_PAUSE` looking around, next point); `e.home` follows the route, so `return` after an investigation brings them back onto it. While `game.alarms` holds, a suspect that acquires an op starts `e.spotT` (`enemyCombat`); `updateEnemy` advances it except while stunned, and at `ALARM_TIME` calls `raiseAlarm`: `game.alarm = { by, x, y, t }` (once per mission), every other active suspect gets `alerted`, `reaction × ALARM_REACT`, turns toward the spot, and the `RESPONDERS` closest investigate it. `drawEnemy` shows the countdown as a red « ! » ring; the HUD objective line and the end score (−5) show the alarm. `raiseAlarm` also calls `assignGuards(free)`: the free suspect nearest each waiting hostage by path (`THREAT_REACH`) gets `e.guard = { h, t, hp, warned, post, look }`; `guardStep` posts him beside the hostage, the hostage between him and the room's nearest door (`roomDoors`), and decays the threat out of sight; in `enemyCombat`, `guardThreat` replaces firing while he sees an op: warning voice and noise, gun on the hostage, and after `THREAT_TIME` s bursts at the hostage (the post is over a cell away so the muzzle stays short of him); a stun resets `t`, a hit makes him drop the hostage, guards never blind-fire or investigate (`hearNoise`). `drawEnemy` draws a dashed line and a filling ring around the hostage. Of the remaining non-responders, `BARRICADE_CHANCE` run `planBarricade` (indoor rooms with one to three doors): `barricadeStep` walks to the inside front of each door, closes it (`doorAction`), locks it (a short `door` action setting `locked`, `lockKnown` false), then posts where it sees the most entrances; `investigate` drops the plan. Patrols close behind them the doors they had to open (`moveAlong` records `e.shutBehind = { d, side }`, `shutDoorBehind` closes it once across and out of the frame). Any engaged suspect may also retreat (`considerRetreat`: wounded below half once with `RETREAT_HURT`, or alone against two ops every 2 s with `RETREAT_ODDS`, twice per game at most): `fallbackSpot(a, threat, toward)` picks the nearest cell by `walkField` within `RETREAT_FAR`, farther from the threat and with a wall (not just a door) between, and `retreatStep` walks there (strafing and firing while engaged, `startBlindFire` refused) before making it the new home, facing the threat.

**Coordinated entry** (`js/game-mates.js`, the AI stacks in `js/game-hunters.js`): a right click released on a closed door (`doorAtPoint`) calls `orderStack(d)`: mates get `order = 'stack'` and an `orderPos` on each side of the frame, on the player's side (`stackPosts` → `stackSpot`, `m.stackSide`), facing the door; `game.stack = { door, side, ready, wait, go, tries, flash, charge, then }`. `updateStack` (from `step`) waits until the door is passable or broken, then `ENTRY_DELAY` (longer while an ops flash is cooking or live), and `endStack` → `launchEntry` turns them into `move` orders to the room corner on their side (`entrySpots`) with a `coverAngle` toward the back of the room. Once `ready`, the stack waits for your choice (`stackWaits`) and the `E` menu offers it (`stackMenu` → `stackChoose(s, choice)`, shared with the strategy door buttons): `'plain'` sets `s.go`, so `stackOpen` has the nearest mate open the door (lock-picking included, four tries); `'flash'` / `'frag'` call `orderFlashEntry(kind)`; `'charge'` calls `orderChargeEntry`: `chargePosts(s, team, stock)` moves every post beyond `CHARGE_NEAR` (`assignPosts`), the nearest mate places the charge in front of the door on the player's own charges (`placeCharge(a, d, side, stock)`) through the AI's `updateChargeEntry`, and the stack waits again; the next choice sets `s.then`, and the charge blows once nobody of the team is within `CHARGE_NEAR` (the AI gives up waiting after 6 s, never on the player, who is told to step aside), then `afterBlast` either enters (phase `'blown'`) or throws the chosen grenade through the breach (`s.flash` with `after: true`). `orderFlashEntry()` (the `E` menu's flash line): `planFlash` picks the thrower and the crack, `updateFlashEntry` runs the phases. In `updateMate`, `stack` moves like `move` but never opens doors and never turns into `hold`; any other order clears `game.stack`.

Trained autonomous agents (`e.drilled`: siege `Operator`s, and the intervention's trinômes on either side) stack on their own (`s.ai` stacks in `game.hunt.stacks`, never in `game.stack`; `game.hunt` exists in siege and trinômes). In `updateAssault`, `considerStack(e)` looks for a closed door on the path (`doorOnPath`, 2.5 U); with at least one free teammate of its group on the same side within `AI_STACK_RANGE`, it rolls `stackOdds(behind)` (`AI_STACK_CHANCE`, `AI_STACK_THREAT` when a `lastKnown` lies behind the door; one stack per `AI_STACK_GAP` and per side, `hunt.stackT[team]`, the same door retried by the same side after twice that, `hunt.tried`) and `formStack(d, side, team, tactic, cmd)` assigns posts with `e.entry = st`, the manner from `pickEntry` (`'charge'` if the team carries one — `WAVE_CHARGES` per wave, set in `spawnAssault` — the door is shut and no found hostage is near; `'flash'` from `AI_FLASH_MIN` operators with a flash left; else `'plain'`). Tests override `stackOdds`/`pickEntry` on the instance. `formStack` also takes `'frag'` (stored as tactic `'flash'` with `st.kind = 'frag'`; a plain `'flash'` takes the kind the team holds in hand) and `'wait'`, and `cmd` marks a stack you command in strategy: it waits for `stackChoose` while `tactic === 'wait'` or its charge is placed without `st.then`, speaks, and never times out. `stackStep` walks each member to its post (`noClosedDoors`) and lets it shoot from there; `updateAiStack` (from `step`) opens the door with the nearest member, reuses `planFlash`/`updateFlashEntry` (silent when `s.ai`), or runs `updateChargeEntry` (the placer stands in front, places, backs off to a post beyond `CHARGE_NEAR`, detonation once nobody is within it). Anything that fails falls back to `'plain'`; an uncommitted stack drops after `AI_STACK_TIMEOUT`. Other operators whose path crosses that door wait. `endStack` gives each member `e.clear` (corner from `entrySpots`, held `AI_CLEAR` s by `clearStep`). `moveAlong` skips a door-middle waypoint once the agent stands in the doorway (`inDoorway`), otherwise two agents side by side in a frame block each other. A second right click on the stacked door enters with the door simply opened (`stackPlain`: `s.go`, opened once the stack is `ready`; with a charge placed, fire then enter); the flash entry is the `E` menu's `orderFlashEntry`: mates carry `MATE_FLASHES` flashes and `MATE_FRAGS` frags (`m.nades`, shown in the squad HUD, kept on `takeOver`). `Game.flashAimFrom(x, y, d, side, crack)` finds a landing point in the room whose straight path crosses the frame (8 px clear of the jambs), stays 9 px off the leaf at that opening (`leafSeg` always swings toward −across, its free end at +along, so a push door is thrown from the hinge side and a pull door from the free end) and passes `clearThrow`. `orderStack` already gives the post that has an angle to a mate with flashes; `orderFlashEntry` swaps posts if needed, falls back to opening wide (`crack` 1), then to `flashSpot` (a free tile on the player's side, off the leaf's swing). `game.stack.flash = { m, crack, depth, kind, phase, g, tries, after }` replaces the normal wait in `updateStack`: `updateFlashEntry` runs place → crack (the mate nearest the door works it via `doorAction`, lock-picking included) → throw (`spawnFlash(..., MATE_COOK, d, kind)`, the door passed explicitly so the grenade slips through; a frag lands `FRAG_DEPTH` in and is never thrown near your own or a hostage) → boom → open → `launchEntry`; it falls back to the normal entry if the thrower drops or the door opens otherwise.

**Teammate orders** (`js/game-mates.js`): `Game.orderFollow`, `Game.orderMove(wx, wy, coverAngle)` and `Game.toggleHold` set `m.order` (`follow` | `hold` | `move`). A held right click builds `game.orderDrag` in `Game.updatePlayer`; on release, the dragged angle is passed as `coverAngle` and stored on the one mate placed on that side as `m.coverAngle`. `Game.pickWatch` returns that angle unchanged instead of scoring watch candidates, and no scan sweep is started while it is set. Any new order clears it. `game.orderTo` (null for the whole crew) restricts orders to one mate: `ordered()` is what `orderMove`, `orderStack`, `orderFollow` and `toggleHold` act on and `orderName()` names in messages; only the `E` menu near a mate sets it, for one order (`kind: 'mate'`, `mateMenu`, through `withOrderTo(m, fn)`; there is no lasting « orders to one mate » mode); a stack only clears when no mate is still in it (`dropStackIfEmpty`). Mates also cuff on their own (`cuffStep`: no target, `follow` or `hold`, the nearest unclaimed surrendered suspect within `MATE_CUFF_REACH`, `e.cuffBy`), summon unaware or stunned suspects before firing (`mateCombat` → `summon(m)`, sharing the player's `shoutT`; `canSummon`), and call contacts (`calloutT`). In escort `vipGuard()` (the last crew mate, or `vipGuardPick`, while following) goes to `guardVipPos`: between the VIP and the nearest visible foe, else behind the VIP away from the player, and keeps moving when engaged.

**Weapons** are real firearms, defined in the `WEAPONS` table in `js/entities.js`:
- Display data (`name`, `maker`, `caliber`, `mode`, `rpm`, `weight`, `mps`, `note`) follows manufacturer specs; the spec sheet shows `mps` on its « Balle » / « Plombs » line, and the fire mode with the rate on « Cadence ». `rof` is derived from `rpm`. The player's speed depends on the total weight of every weapon carried, in hand or slung, accessories included (`Player.weaponLoad` → `loadMobility(kg)` in `js/entities.js`, 3.5 % per kg, clamped to `MOBILITY_MIN`..`MOBILITY_MAX`), not on the weapon in hand; vests and shields multiply it by their own `mobility`. Keep new weapons consistent with real data.
- Ballistics: one cell `U` is one metre. `mps` is the real muzzle velocity (m/s, service load), `speed = mps × U` px/s is derived in the loop at the end of `WEAPONS` (AI weapons take their `pickup` model's, the sawn-off `sgE` has its own; a subsonic load caps it at `SUBSONIC.mps`). A bullet crosses a room in one frame: `updateBullets` sweeps the segment travelled (`castRay` plus a segment test per candidate, so nothing tunnels), caps it by the bullet's remaining `life`, and pushes it to `game.tracers` (`{ x0, y0, x1, y1, t, heavy }`, aged in `step`, gone after `TRACER_LIFE`), which `Renderer.drawBullets` draws; bullets themselves are not drawn. Every bullet flies `BULLET_REACH` (80 m, beyond every map) unless something stops it, so `range` is only the AI's useful range (`fireRange`, `startBlindFire`); `effRange`/`rangeSpread` model precision falloff. Fast bullets are what keeps mutual kills rare (a target hit no longer gets 0.3 s to fire back).
- Tuning fields (spread, bloom, range falloff, `pellets`, `pattern`) are combined by `Game.spreadOf` and `Game.fireWeapon`. `spread` is the shooter's aim error, drawn once per shot; a shotgun's pellets then open by `pattern` around that aim (00 buckshot, about 1.5°), so `lineOfFireClear` and the crosshair add `pattern` to `spreadOf`. AI weapons (`ak`, `pistolE`, `hk416op`, `akH`, ...) have `mag: Infinity`, no `cat`, and take their `rof` from the real model they turn into when picked up (`pickup`), unless one is given (`pistolE`). Every AI shooter fires bursts of `w.burst` separated by `w.pause`: AI weapons set them, player weapons (carried by mates) get them in the derivation loop at the end of `WEAPONS` (3 in auto, 2 in semi, 1 for the pump; pause `BURST_PAUSE[mode] + BURST_RECOIL × recoil`). `Game.endBurst(a, w)` starts the next one (±1 shot, pause ±`BURST_JITTER`) for `enemyCombat`, `blindFire` and `mateCombat` alike; mates track `burstLeft`/`pauseT` like enemies, so a pump or a pistol never fires faster than its `rof`.
- `kind` selects the drawing in `Sprites.gun` (`rifle`, `smg`, `pdw`, `shotgun`, `pistol`, `ak`, `sniper`); `tint` selects a colour/shape variant; `snd` sets the shot sound.
- `reloadType: 'shell'` loads one shell per `reload` seconds, and firing interrupts it.
- Nobody is armed the same: `dealWeapons(pool, n)` (in `js/entities.js`) draws without repeats from `MATE_POOL`, `SIEGE_MATE_POOL` or `OPERATOR_POOL` (`hk416op` twice, `scarhop`, `mp5op`, `mp7op`, `m870op`); `loadLevel` deals the mates' weapons. Every AI group's kit (siege waves in `spawnAssault`, trinômes in `spawnSquad`) comes from `Game.squadKit(camp, n, type)`: `[{ weapon, acc, shield }]` from the leader down, dealt from the camp's pool with `ROLE_KITS` by rank, and for the police, with `OPERATOR_SHIELD_CHANCE`, the leader swaps to `glockop` and one of `OPERATOR_SHIELDS` (the breaching charge then goes to the next man); a strategy `type` fixes everything from `GROUP_TYPES` instead. Suspects pick at random from the mission's `enemyWeapons`.
- Reloading animates: `reloadT` is paired with `reloadDur` wherever it is set (`startReload`, `Game.mateReload`), and `actStyle` synthesises `act: { type: 'reload' }` so `Sprites.actionPose` plays the magazine change (`st.mag` is the magazine in hand). `mateReload` scales the duration for `reloadType: 'shell'`.
- `PRIMARY_WEAPONS` and `SIDEARMS` list what the briefing screen offers. The player's choice is `game.loadout` = `{ primary, sidearm, shield, acc, teamSup, cutPower, vest, nades, army }` (`army`: strategy only, see **Strategy mode**), stored in `localStorage` under `breach.loadout.<mode>`, completed by `Game.normLoadout` (which also turns an old team-wide `sup` flag into per-weapon suppressors) and applied via `Game.setLoadout` → `Player.equip`.
- Grenade kits: `NADE_KITS` in `js/entities.js` (`loadout.nades`: `flash` 3 flashes, the default; `mix` 2 + 1 frag; `frag` 2 frags), offered in the police camp's briefing by `UI.nadePicker` (`.nadebtn`, between the vest and team rows); `Game.armGrenades` applies it (the armed camp always gets two frags; a mate taking over keeps its own grenades). Every agent holds `a.nades = { flash, frag }` and `a.nade` (the kind in hand, the one the AI throws on its own: flashes for the police, frags for the armed group); `Agent.flashbangs` is a getter/setter on `nades[nade]`, so code written for a single-kind counter keeps working, and the other kind only leaves on an order (frag entries, strategy `N`; strategy police trinômes carry `STRAT_FRAGS`). `N` (`Game.cycleNade`) switches kind; `nextNade` brings the other kind into hand once the last of one is gone. The kind is fixed when the pin is pulled (`throwFlash` → `p.cooking.kind` → `spawnFlash(..., kind)`). Mates keep `MATE_FLASHES` and `MATE_FRAGS` for grenade entries; `updateStack` also waits for the player's own frag. The HUD shows the kind in hand (`#nadeLabel`, `NADE_NAMES`) and the other one in `#nadeOther`.
- Accessories are per weapon: `loadout.acc[key] = { sup, laser, light, grip, mag, scope }`, set from the briefing by `Game.setAccessory`. `fittedDef(key, acc)` returns the cached fitted variant (`suppressedDef(key)` is the suppressor-only one), ignoring what the weapon cannot take (`SUPPRESSORS`, `LASERS`, `LIGHTS`, `GRIPS`, `MAGS`, `SCOPES`); `makeSlot(key, acc)` builds a slot from it. A fitted def keeps `d.acc` (what is mounted), so `Game.pickupSlot` rebuilds the picked-up weapon with the same accessories; an AI weapon (no `cat`) looks its accessories up under its `pickup` key, keeps its infinite magazine (the extended one only changes the drawing) and has no weight. `accFits(key, name, m)` says whether a weapon takes an accessory in mode `m`: `SQUAD_KIT` lists the armed group's trinômes-only kit (PBS suppressors on the AKs, Uzi and Škorpion cans, rail handguard for laser, lamp and grip on the AKs, drawn by `Sprites.gun` as a dark railed handguard); `UI.accRow`/`accNotes` grey them out elsewhere with the reason, and `normLoadout` strips them. Every AI trinôme member is fitted by rank from `ROLE_KITS` (the crew in `squadsArmed` takes the second and third), and siege waves too (first wave suppressed, later ones with lasers). The foregrip scales `bloom`, `bloomMax`, `recoil` and the AI's `pause` by `GRIP` (`tint.grip`); the extended magazine sets `mag` and multiplies `reload` from `MAGS`, reserve unchanged (`tint.extMag`: a length ratio, `'drum'` or `'tube'`, drawn by the `mag` helper in `Sprites.gun`). A laser (`w.laser`, `tint.laser` draws the module, `LASER_MOUNT` in `js/sprites.js`) multiplies the movement spread by `LASER_MOVE` in `Game.spreadOf` while `Game.laserLit` holds (on, and the gun not lowered by an action, reload, fiber or cooking). `Game.laserBeam` is the beam (muzzle to the first sight blocker or person); `step` keeps every lit one in `game.beams` (the player's, and AI agents whose weapon has a laser: they carry `laserOn = true`) and the player's in `game.beam`, and `Game.spotLaser` (from `updateEnemy` and `updateAssault`) lets an idle agent who sees a point of a beam of the other team turn toward the source and, above `SUSPICION_GO`, investigate. `Renderer.drawLaser` draws them under the vision clip. The scope (`SCOPES`, `w.scope`, `tint.scope` `'top'` or `'side'` for the AKs' PSO-1) only works while `Game.scoped(a)` holds: the gun in hand has one, `a.stillT` (time stopped, kept in `step` for every agent) has reached `SCOPE.settle`, and no action, reload, fiber, cooking or stun. It then halves the base spread and stretches `effRange` in `spreadOf`, stretches the bullet's range in `fireWeapon` (`SCOPE.reach`), and `Game.viewOf(a, ang)` lengthens sight by `SCOPE.sight` within ±`SCOPE.half` of the aim — used by `canSee`, `seesSpot`, `sightOf`, the target checks of `enemyCombat` / `mateCombat` and the vision cones (not in the dark). `Renderer.updateCamera` then holds the aimed world point in `renderer.scopeAim` (taken under the cursor when the scope comes up, moved by `pointerMove`, kept on screen) and glides the camera to `SCOPE.lead` of the way from the player to it, capped at `SCOPE.look` of the half-screen; the drawn cursor is reprojected onto that point, so the aim never drifts and a cursor caught at the screen edge gets room to push further; `drawCrosshair` adds a blue ring and the HUD shows `#scopeMode`.
- Precision rifles (`cat: 'sr'`, `kind: 'sniper'`): `trg22` (police, bolt action, mode `'Verrou'`: `Sound.cycle` after each shot) and `svdP` (armed), with AI versions `trgop` / `svdH` for the strategy precision group's marksman. Their scope is built in (`scope: true`, `optic` naming an entry of `SNIPER_OPTICS`), so `SCOPES` has no entry for them and the scope button is greyed; `scopeOf(w)` returns that optic or the plain `SCOPE`, and every scope effect reads it (`spreadOf`, `scoped` settle, `viewOf`, `fireRange` capped at `AI_SNIPER_RANGE`, the camera's `lead` / `look`, the briefing bars and texts). An optic's `view` makes `Renderer.updateCamera` pull the on-foot zoom back (`scopeK`, applied to `footZoom` from `fitZoom`). In the briefing each weapon category's name sits left of its cards (`.loadout .wcat`), which keeps the screen from scrolling.
- Vests: `VESTS` in `js/entities.js` (`loadout.vest`, assault only, `MODES[mode].vests`, default `vestL`; `normLoadout` fills it in), toggled by `#ovVest` in the briefing. `Player.equip` sets `player.vest`; `updatePlayer` scales speed by `vest.mobility`; `Game.vestHit(c, b, ang, dmg)` (bullets in `updateBullets`, and what passes through a shield in `shieldHit`) leaves `blunt` of the damage when `b.pen ≤ vest.soft`, or `plateBlunt` within ±`arc` front or back when `b.pen ≤ vest.plate`. Only the player wears one; `st.plates` draws the heavy one. The briefing shows every vest of the mode side by side (`UI.vestPicker`, `.vestbtn`, the worn one `.sel`), and the HUD names the vest and shield worn next to the health bar (`#gearLabel`).
- Shields: `SHIELDS` in `js/entities.js`, chosen instead of the primary (`loadout.shield`, assault only, `MODES[mode].shields`). `Player.equip` then keeps only the sidearm (plus `SHIELD_EXTRA_MAGS`) and narrows `fov`; `updatePlayer` scales speed by `shield.mobility`, `spreadOf` multiplies by `shield.aim` (half the penalty with a laser), and `nearestDrop` only offers pistols. In `updateBullets` a carrier has an arc of ±`shield.arc` at `SHIELD_REACH` in front of the body circle; a bullet entering it goes to `Game.shieldHit`, which stops it if its `pen` (penetration class from the weapon: 1 handgun/9 mm/buckshot, 2 for `mp7`/`tt33`, 3 rifle) is at most `shield.stops`, else deals `through` of the damage. `Sprites.shieldHeld` draws it on the arm (`shieldStyle` in `js/render.js`, also in `enemyStyle`), `Sprites.shieldFlat` dropped by a body and on the briefing card. AI agents carry one too (`Game.armShield(a, key)`: `a.shield`, speed × `mobility`, `fov` capped; a pistol from `squadKit`), and `takeOver` keeps it (with `SHIELD_EXTRA_MAGS`). `Game.shieldStops(c, a)` says whether `c`'s shield faces `a` and stops its `pen`: hunters' `acquireFor` counts such a target `SHIELD_SHUN` farther, `enemyCombat` switches a hunter off it to another visible foe, and `updateAssault` has an armed hunter throw a frag at it (`maybeFlash`).
- The briefing icons (`UI.drawWeapon`) reuse `Sprites.gun` at one shared scale, so relative sizes match the in-game drawings.
- The briefing (`UI.showBriefing`) must fit one screen without scrolling: three columns, left the plan and the entry (click a breach on `#ovPlan`, or its button; the base in total war), middle the weapon cards (`CARD_SCALE`), the accessory rows (`#waccs`, always two rows of six buttons under the weapon name, greyed for a shield) and one line with the vest and teammates' suppressor toggles, right the two spec sheets (`#wdetail`). The sheets never move when the choice changes: `.brief-specs-in` is absolutely positioned so they take the height of the other columns, half each, and every sheet built by `UI.fiche` has the same skeleton (one-line head, bars on 7 fixed rows, 8 specs, then text that scrolls on its own). Keep that skeleton when adding a field. Above the sheets, `#wsum` (`UI.gearSummary`, fixed height, refreshed by `refreshLoadout`) sums up the kit: total weight, speed as the same product as `Game.updatePlayer` divided by `MOBILITY_MAX` (so never above 100 %), and with a vest or shield the share of damage taken by threat (pen 1, pen 3) and side, mirroring `vestHit` / `shieldHit` — update it if those change. Accessory and vest buttons carry small SVG icons drawn by code (`ICONS`, `UI.icon(name)`, `currentColor`). The key list lives in the help screen (`Commandes` button, `showHelp(back)`).

## Tests

`tests/index.html` loads the game scripts plus `tests/tests.js`, runs every scenario synchronously on a hidden canvas and HUD, and sets `document.title` to `PASS` or `FAIL n`. Headless: `chrome --headless --allow-file-access-from-files --dump-dom tests/index.html`. `mkGame(opts)` builds a game (`mode`, `level`, `loadout`, `entry`); `checkEnd` is stubbed by default because a finished mission freezes `update`, `alone: true` removes enemies and mates so the player is not shot mid-measurement, and `noEnemyAI` freezes suspects. `mkGame` also pins `entryRandom = false`, since the entry is otherwise random, turns off random locks (`lockDoors`, unless `locks: true`), patrols (`patrols`, unless `patrols: true`), the general alarm (`alarms`, unless `alarm: true`) and score records (`saveRecords`). Tests that go through `setMode`, `setEntry` or the start screens (mode cards, camp buttons) save and restore `breach.mode` / `breach.entry`, so they leave `localStorage` as they found it; none calls `setLoadout`. `HOSTAGE_LEVELS` (assault and siege maps, without duplicates) and `ALL_LEVELS` (every mode's maps) feed the map checks; `mkGame({ level })` indexes the mode's own list. The total war scenarios run the simulation with `game.update` only (no drawing) when they need tens of seconds of battle. `aiStack(g, d, side, tactic)` sets up a siege wave of three blind operators in front of a door with a forced stack. `openE(g)` / `pickE(g, id)` / `pressE(g)` drive the `E` menu (`pressE` is « E, E », the default action), `readyStack(g, w, D)` puts your crew in a ready stack on a door, and `doorButton(g, d, id)` clicks a strategy door button. `tests.js` replaces `Sound.init` with a no-op (a briefing click would otherwise start audio for the rest of the suite; only the master-output test calls the real one, `SOUND_INIT`, and restores `Sound.ctx` / `Sound.out`). `withRandom(v, fn)` pins `Math.random` for a decision (retreats, barricades, summons); tests that set a heard squad contact pass `decided: true` so no random ambush interferes. `COVER_ROOM` is a small room with a low wall for the cover scenarios (`game.map = new GameMap(COVER_ROOM)`). Add a scenario for every behaviour fix.

`tests/run.sh` finds Chrome, Chromium or Edge (or `CHROME=`), loads `tests/index.html?grep=…` headless and prints the summary and failures; exit code 0 on `PASS`. `.github/workflows/tests.yml` runs it on every push and pull request. `tests/sim.html` (`tests/sim.js`) is the balance bench: simulated games with the player out of play (`commander`), no drawing, scenarios `squads`, `duel`, `war` (strategy with every group sweeping), `defense`, `siege`, parameters `n`, `level`, `time`, `camp`, `army` (the strategy group types, comma-separated) and `sup=1`; it writes a report into `#report` and sets the title to `DONE` (`bash tests/run.sh --sim 'scenario=war&n=6'`). Use it to measure a tuning change instead of a scratch script.

## Breaches (entries from outside)

`X` (exterior door) and `W` (window) sit in the outer wall. `GameMap.addBreach` records each one in `map.breaches` with its `inside` point (the walkable tile on the building side) and inward `angle`; `breachLabel(b)` names it by compass side. An `X` is a normal door; a `W` is `map.windows` / `windowAt`: floor tiles (so sight and bullets pass) that `blocksMove` refuses, so nobody walks through. The outside is void, so nobody can leave. In assault mode the player starts at `breaches[game.entryIndex]`, drawn at random on every load while `game.entryRandom` holds (the default, saved under `breach.entry` and set from the briefing through `Game.setEntry(i | null)`), one map cell inside (`Game.entryStart`, so mates are not pinned against the façade). The entry zone is empty: `GameMap.roomOf(x, y)` flood-fills the room (stopping at walls, doors and windows) and `Game.clearEntryZone` moves any enemy or hostage found there to the nearest free tile outside it. The maps already respect this; the guard is a safety net; in siege mode `spawnAssault` rotates waves across breaches and gives each operator an entry gesture (the door opening, or 1.3 s to climb through a window).

## Game modes

`game.mode` is `'assault'` (the original), `'siege'`, `'escort'`, `'squads'`, `'squadsArmed'`, `'war'`, `'warArmed'`, `'strategy'`, `'strategyArmed'` or `'strategyAssault'`, saved in `localStorage` under `breach.mode` and switched via `Game.setMode`, which reloads the level. `MODES` in `js/entities.js` holds each mode's map list (`levels`, every mode its own: `ASSAULT_LEVELS` and `SIEGE_LEVELS` are the shared hostage buildings `LEVELS` plus maps of their own, then `ESCORT_LEVELS`, `SQUAD_LEVELS`, `WAR_LEVELS`; `Game.levels` returns the current one and `loadLevel(i)` indexes it), its button text (`pitch`) and description (`desc`, from `MODE_DESC`), weapon lists and default loadout (`POLICE_GEAR`, or `ARMED_GEAR`: the armed side fields `akP`, `ak74P`, `uziP`, `skorpionP`, `m870`, `makarovP`, `tt33`, `glock17`), its `camp` (`game.camp`: `'police'` has flashes, charges and the fiber; `'armed'` has frags and neither), `power` (the lights can be cut), `squads` (autonomous trinômes on both sides: trinômes, total war and strategy), `war`, `strategy` and `defense` (strategy against an entrenched armed group, see **Strategy assault**). Switching modes keeps the current map if the new list holds it too (assault ↔ siege on `LEVELS`), else goes back to the map last played in that list (`game.levelMemo`); loadouts are stored per mode (`breach.loadout.<mode>`). A mode with `variantOf` shares the other's mode card: `squadsArmed` / `warArmed` are trinômes / total war played from the armed side, picked by the camp buttons in the briefing (`.campbtn`, `UI.campRow`, generic over the variant pair).

**Start screens** (`js/ui.js`): the player picks the mode, then the map, then the gear. `main.js` opens `UI.showModes()` (one `.modebtn` card per non-variant mode, with `desc` and its map count) → a click calls `setMode` then `showLevels(back)` (the mode's maps, `.levelbtn`, plans by `UI.drawPlan`, `#ovModes` back to the modes, `#ovClose` only when a `back` screen is given) → a click calls `loadLevel` then `showBriefing()`. All three set `game.paused` (`loadLevel` unpauses). `UI.steps(at, mode, map)` draws the « 1. Mode › 2. Carte › 3. Équipement » trail; in the briefing its past steps are the buttons `#ovModes` and `#ovLevels`. Pause and end screens offer `#ovLevels` (« Cartes ») and `#ovModes`.

**Autonomous agents** (`a.hunter`): any agent driven by `Game.updateAssault`, on either team — the siege `Operator`s, and in trinômes the second trinôme of your side (in `game.mates`, so it counts in `ops`, vision, the HUD and the relay) and both opposing ones. `step` dispatches on `hunter` for mates and enemies alike; `teamOf(a)` / `foesOf(a)` give its allies and targets, `game.crew` is the player's own mates (the only ones `orderMove`, `orderStack`, `toggleHold` and `orderFollow` touch). Hunters never blind-fire, keep fire discipline (`lineOfFireClear`, trained) and converge on what they hear from the other side (`hearNoise` → `know`). Allied noises never turn their head; an allied shot heard loud (`HEAR_GO`) from another group with a fresh contact makes them adopt that contact (reinforcement).

Sweeping (`updateAssault` → `assaultGoal` → `sweepGoal`): the next sector is decided for the whole group (`group.sweepTo`; a groupless siege operator keeps its own) and kept until it is cleared, so the group never changes its mind on the way. `markSwept` (every 0.25 s per agent) clears every sector within 1.4 U, or within `SWEEP_SEEN` with line of sight. `pickSector` scores the remaining ones by walking distance from the group's most central member (`anchorOf`, `GameMap.walkField`), minus `SWEEP_AHEAD` × the cosine to the direction of the last pick (`sectorDir`), and leaves to the others what is closer to another group sweeping the same list (the two opposing trinômes share one, see **Trinômes**) or, for your autonomous trinôme, to you. An ordered lane (`pingpong`, total war) is rejoined at its nearest step, earlier steps marked done, and reversed once finished. Unreachable sectors are marked done; with nothing reachable it waits a second (`pickAt`) before recomputing. The old order (first undone sector by straight-line distance from the entry) made groups zigzag across the entry; the scratch simulations of the 2026-10-18 rework went from 18 to 4 U-turns per agent per minute. A path to a goal carries `path.to`, and `updateAssault` re-paths as soon as the goal moves by 1.5 U, instead of finishing the old path.

**Trinômes** (`game.squads = { groups }`): `loadLevel` places the player and two mates as in assault (no locks, patrols, darkness, hostages or posts), then `startSquads(entryBreach)` picks the breaches — the opponents' two farthest by walking distance among those out of sight of yours (`apart`), your second trinôme's the nearest one apart from theirs, else yours — and `spawnSquad(b, team, camp, taken)` places three at each (`breachFile`, which falls back to the nearest free cell of the arrival room). A group is `{ team, camp, breach, contact, search, sweepTo, members, sectors }`: its own `buildSectors(null, b.inside)` sweep (the two opposing groups share one list, `startSquads`), and `contact` (`{ x, y, t, seen, foe }`), set by `know(e, x, y, seen)` whenever a member sees (`seen` is the foe, or the laser's owner) or hears an opponent. `know` keeps a contact younger than `CONTACT_HOLD` against a noise if it was seen, against a second foe in view for 0.5 s, and against a noise elsewhere unless the new one is a cell closer; otherwise every shot of the battle would turn the group. A group moves as a file behind a leader, like your crew behind you: `leaderOf(g)` is its first standing member (`spawnSquad` puts the deepest one first, `breachFile(...).reverse()`; `baseFile` already sorts forward), and only the leader navigates — to `contactGoal` (dropped after `SQUAD_CONTACT` s), else `group.search`, else the sweep, never to its own `lastKnown`. Reaching an empty contact, it clears it and starts `group.search` (`searchStep`: `SQUAD_SEARCH` s holding, each member looking its own way, a straggler joining first), then the sweep resumes. Out of a fight the leader walks at `SQUAD_PACE` (`agent.pace`, reset each frame by `updateAssault` and read by `moveAlong`; `stepNoise` is silent below 1), holds `SQUAD_DOOR_PAUSE` on the threshold of each door it crosses (`doorPause`, through `doorAhead`, which `doorOnPath` uses too) and `waitsForGroup` stops it while a follower lags beyond `SQUAD_SPREAD` (straight or walking distance, `pathLeft`), `SQUAD_WAIT` s in a row at most; a contact seen less than 2 s ago lifts pace and pauses. The others run `followStep`: their place is `formationPos(e, lead, SQUAD_FILE[rank], heading)` (the crew's formation code, which takes any leader and heading; `inAimCone` takes the leader too), refreshed every 0.15 s (`e.formAt`) and reached by `noClosedDoors` routes (else straight to the leader, doors included) — at the leader's pace when close, a bit faster up to `SQUAD_CATCH`, running beyond, never backing up to a place less than 1.5 U behind. Walking, they look aside through `agent.watchDir` (honoured by `moveAlong`, which also keeps a hunter's `moveDir`): the second left, the third right with a look back every 5 s, a fourth (strategy assault group, third entry of `SQUAD_FILE` / `SQUAD_LINE`) to the rear; halted, the second left, the third right if there is a fourth, else to the rear. When the group has just seen a foe, a follower that does not see it goes to `firingSpot`, else comes abreast of the leader (`SQUAD_LINE`, in the frame of the foe's direction). `trackStuck` (shared with `updateMate`) unblocks followers. The squad HUD says « En tête » / « Suit ». Groupless siege operators keep their old full-pace progression. Police trinômes are `Operator`s (one charge per trinôme, `WAVE_CHARGES`); armed ones are `Enemy` with `hunter`, `SQUAD_MILITANT` stats, `akH` / `ak74H` (`MILITANT_POOL`, AI versions of the player's AKs, fitted by rank from `ROLE_KITS`) and two frags, thrown by `maybeFlash` from `FRAG_RADIUS + U` and never near their own; `drilled` unset, they stack less often (`stackOdds(behind, e)`, `AI_STACK_ARMED`) and their `'flash'` entry throws a frag (`planFlash` asks `flashAimFrom(..., minDepth)` for `FRAG_DEPTH`, `updateFlashEntry` aborts near their own or hostages, `pickEntry` never near a hostage). Every AI trinôme is fitted by rank from `ROLE_KITS` (leader suppressor, second laser, last extended magazine; siege waves: suppressor for the first, laser after), and `updateAssault` keeps an AI laser off unless it has a target or a fresh seen contact. The leader of an unordered group runs `groupTactics`: with two men or fewer facing more foes seen within `GROUP_RETREAT_SEEN` (`g.seen`, filled by `know`), `g.retreat` to a `fallbackSpot` (toward the base or breach), followers keeping file (no firing spots) and nobody stopping to shoot; on arrival `g.ambush`. A heard contact within `AMBUSH_RANGE` is decided once (`contact.decided`): with `AMBUSH_CHANCE` (`AMBUSH_CHANCE_ARMED`) `setAmbush` picks the first door or the point four cells along the path and a spot with a view of it; `ambushStep` holds it and `followStep` lines followers up like a `hold` order, until `AMBUSH_TIME` or a seen contact. `radioStep` (from `step`, twice a second) passes fresh seen contacts between groups of a team (in total war within `RADIO_RANGE`) and what the player and crew see to the allied groups, as heard contacts. In this mode bullets of either side hit their own (`updateBullets`), shouting is refused, the player's armed mates get no handgun-only weapon (`Game.crewDefs`, which deals every crew's weapons), and `takeOver` hands over to the crew first, then to a hunter of your side (taken off its group). `checkEnd` ends the game when one side is down; `scoreReport` scores the side left standing and the kills. `SQUAD_LEVELS` are symmetric arenas with at least four well-separated breaches and no spawns. A sector a hunter cannot path to is marked `done` (`updateAssault`), so it never stalls on it.

**Total war** (`game.war`, also `game.squads`, modes `war` / `warArmed`, `WAR_LEVELS`): two armies of three trinômes, `WAR_TIME` (300 s). Battlefields have two base zones, `'1'` and `'2'` (`map.bases`: `{ id, cells, at, cx, cy, angle }`, each facing the other; `GameMap.baseLabel`), and no breaches. `loadLevel` picks the player's base with `entryIndex` / `entryRandom` (the same choice as the assault entry, over `map.bases`), starts the player there (`baseStart`), then `startWar` builds `war = { bases, camps, slots, respawn, kills, mine, reinforce, pruneT }` and reveals the whole map. `slots[team][k]` is each army's current trinôme k: the player's own is `slots.ops[0]` (`{ crew: true, members: [player, mates] }`), the others come from `warSquad(team, k)` → `spawnSquad(gate, team, camp, taken, { pts, names })` with places from `baseFile(base, n, taken, lane)` and names from `WAR_DEFS`. Each autonomous trinôme has a lane (`Game.warLane`: yours on the flanks, theirs 0–2): `warSectors` cuts the field in three bands along base 1 → base 2 and keeps one step per `WAR_STEP` of progress, closest to the band's middle; `group.pingpong` makes `pickSector` rejoin it at the nearest step after a detour and walk it back once done. `updateWar` (from `step`) notices a trinôme with nobody standing, announces it and brings it back after `WAR_RESPAWN` s — `warCrew()` for the player's (a new `Player` with the briefing loadout and two new mates; the old body stays in `mates`), `warSquad` otherwise — and calls `pruneBodies` every 5 s (bodies older than `WAR_BODY_LIFE` and out of sight leave `mates` / `enemies`; `damage` stamps `diedAt`). The relay only goes to the crew (`step`, `takeOver`): with the crew down the player waits for reinforcements. `damage` credits every death to the other army (`war.kills`, `war.mine` for the player's kills); only the player's own hits count in `stats.friendly`. `checkEnd` ends at `WAR_TIME` with `'win'`, `'lose'` or `'draw'` (emitted like the others; `scoreReport` caps a draw at 69 and C). The HUD timer counts down, the objective shows the tally and the reinforcement countdown, and the squad box lists the three current trinômes (`UI.squadRows`). The briefing's left column is `UI.basePicker` (plan with the bases, `.entrybtn` per base) plus `campRow`; `Sprites.paintBases` hatches the bases on the floor (yours blue, `Renderer.homeBase`), the minimap colours them too.

Every hostage map (`ASSAULT_LEVELS` and `SIEGE_LEVELS`) has 9 enemy spawns and 3 to 5 hostages (3, 4 and 5 on the first three maps, 4, 4 and 5 on Hôtel, Banque and Centre de données, 4 on the two outdoor maps, Maison de maître and Corps de ferme, and on Musée, Mairie and Supermarché) — those counts are what `loadLevel` spawns; keep them when editing maps. The positions themselves are drawn per game by `Game.buildPosts`, which shuffles the map's own spawns together with a grid of free tiles, keeps them 2 U apart (1.2 U if a map is cramped) and skips the assault entry room. In siege the player takes the first drawn post, so the leader moves around too. In siege mode the mates take no orders: `Game.canCommand` refuses `T`, the right click and every `order*` call, so each militant holds its post.

In siege mode `loadLevel` reassigns the roles without touching the engine's notion of sides: the player and `mates` (from `SIEGE_MATE_DEFS`, militant styles, `ak`/`pistolE`) stay team `ops` and start on the enemy spawns, while `enemies` becomes the assault team — `Operator` instances spawned at the map entry with `hk416op`/`mp5op`. Everything that keys off `ops` (vision, fog, friendly fire, orders, HUD squad) therefore works unchanged.

`Game.startSiege` builds `game.siege` (prep timer, `waves` copied from `SIEGE_WAVES` at the top of `js/game-siege.js` — one entry per wave, its size — plus breaches and sector list) and reveals the whole map as explored, since the defender knows the building; the first wave only enters when the prep timer runs out. `Game.updateAssault` replaces `updateEnemy` for those operators (and every hunter): it reuses `enemyCombat`, throws a flash through `maybeFlash`/`spawnFlash` when it knows where the threat was, stacks on closed doors from time to time (see **Coordinated entry**), and walks to a found hostage, else the last noise heard, else the nearest sector from `Game.buildSectors` (`sweepGoal`, see **Autonomous agents**). `updateHostageRescue` marks a hostage `found` when an operator sees it; `assaultGoal` sends operators to found hostages nobody escorts yet, and the first one to reach a hostage escorts it out (see **Hostages**). `updateSiege` sends the next wave `gap` (6 s) after the current one is wiped out, or `maxGap` (30 s) after it entered if it still holds; the UI texts read the wave count from `SIEGE_WAVES`. The prep countdown, each wave's arrival (for `WAVE_BANNER` s, with its breach) and the countdown to the next wave once one is wiped out show in a banner in the middle of the screen (`UI.updateWave`, `#waveBanner`, read from `siege.prep`, `arrival` and `nextWave`), not as `say` messages. Grenades: `Game.armGrenades` gives the assault side its briefing kit (flashes by default, see `NADE_KITS`) and the siege side two frags (`'frag'`, same `flashbangs` counter); a grenade carries `kind`, `team` and `thrower`. `detonateFrag` damages everyone in `FRAG_RADIUS` with line of sight (so walls and closed doors protect), thrower and hostages included. `detonateFlash` spares the thrower's team (they look away) beyond 1.2 U. `maybeFlash` only throws when `Game.clearThrow` finds a free trajectory (no wall, prop or non-open door) and no operator stands near the aim point. The siege side has no fiber optic. `separate` pushes apart agents that sit exactly on top of each other, and `spawnAssault` never places two operators on the same point. The end screen counts losses over the whole group: `game.squadSize` (player + mates, set in `loadLevel`) against the dead in `game.ops`. `checkEnd` branches per mode: in siege you win once the last wave has entered and no operator is alive, and lose if you die or no hostage is left alive in your hands (all dead, or dead and evacuated); a single hostage death only announces how many remain. In assault, `checkEnd` wins as soon as every suspect is down, whether or not the hostages are out (a dead hostage still loses first); `objectiveCues` announces once that all hostages are out while suspects remain. `Game.noise` also turns mates toward nearby noise without moving them.

## Strategy mode

`'strategy'` / `'strategyArmed'` (`MODES[mode].strategy`, also `war` and `squads`, on `WAR_LEVELS`) is total war commanded from above, RTS-style. `loadLevel` sets `game.strat` (`{ sel, box, aim, hover, frozen, zoom, camTo, miniDrag, keyAt, clock }`, null in other modes) and builds no crew; `startWar` then turns `game.player` into a **commander** (`alive = false`, `commander = true`, parked on the home base: never drawn, never relayed, never targeted) and spawns all three `war.slots.ops` with `warSquad` (names from `STRAT_DEFS`, colour `STRAT_COLORS[k]` copied to every member's `accent`, `group.label`, `group.queue`, `group.rush`, `group.order` = hold at the base). Respawned groups come back the same way and keep their slot, so the selection (`strat.sel`, a set of slot indices) survives. `war.lost` counts annihilated ops groups; `scoreReport` has a strategy branch (`armySize()`: the men the army starts with).

Group types: each of your three groups is of the type chosen in the briefing, `loadout.army[k] = { type, sup }` (`normLoadout` defaults to `DEFAULT_ARMY`, three `normal`; `Game.setArmy(k, o)` → `setLoadout`, which reloads the level when `army` changes). `GROUP_TYPES` (`js/entities.js`) gives each its size `n`, its weapons per camp and rank (`arms`), the police leader's `shield` (the assault group's heavy shield; the armed camp has none) and the rank of the marksman (`scope`; the precision group's marksman leads, so he holds the given direction, without the leader's sway in `holdStep`); `sup` puts a suppressor on every weapon that takes one. `warSquad` passes it to `spawnSquad(…, { type })` (`group.type`), which places `n` men (`baseFile`); `STRAT_DEFS` names four per group. The opposing army stays three plain trinômes. Player-facing strategy texts say « groupe », not « trinôme ». The briefing's `armyList` puts type and mode buttons on each group (`.armybtn`, `data-k` with `data-type` or `data-sup`), and the sidebar card shows the type.

Input: `Game.update` calls `updateCommander(dt)` before `step`, even during the tactical pause (`strat.frozen`, `Space`: `step` and `updateDying` are skipped, the renderer stops the walk cycles). It reads `input.mouse` (`ppx` = world px per CSS px, `mini` = cursor over the minimap, `ui` = over the sidebar, `item` = door button under the cursor, all set by `main.js`; `Mouse0Up` is a new pressed code), computes `strat.hover` (`stratHover`: visible foe, own unit, closed door; nothing over the sidebar) and `strat.menus` (`stratDoorMenus`), and dispatches: a left click on a door button → `menuPick`; with `strat.nadeAim` set (a sidebar grenade button), the next left click → `stratGrenade(gs, x, y, kind)` and a right click cancels; left click / drag → `stratPick`; `1`–`3`, `KeyQ` (A on AZERTY), `F` → selection and `strat.camTo`; right click → `stratRightClick` → `stratAttack` / `stratDoor(gs, d, 'choose')` / `stratMove` (delayed by `DOUBLE_RIGHT` through `strat.click`, on the strategy clock `strat.clock`; a second press there opens `strat.zone`, the zone menu: `stratOpenZone` / `stratZoneMenu` (grenades through `stratThrower`, attack, stack, move, rush), driven by `stratZoneInput` — wheel, `E`, or a click on a line (`mouse.item.zone`) — and drawn with the door menus) (spreads several trinômes `STRAT_SPACING` apart, `freeSpotNear` snaps points, Shift queues); `H` `stratHold`, `R` `stratSweep`, `C` `stratRush`, `G` (flash; frag for the armed camp) and `N` (frag) `stratGrenadeKey` (on a closed door: a stack entering that way), `B` `stratChargeKey`; the wheel accumulates `strat.zoom`. The sidebar (`#stratPanel`, see Rendering) calls `stratCommand(id)` (`sel0`–`sel2`, or an id of `stratCommands()`, the list it draws with labels, keys, counts, `off` reasons and `on` states). Every new order goes through `releaseGroup` (drops its stack, clears `clear`, paths, search).

Execution: in `updateAssault`, a group with `group.order` goes to `orderStep` instead of contact/search/sweep (`order === null` is the total-war lane sweep); in the target branch an ordered group (other than `attack`) fires but does not chase, and `maybeFlash` throws nothing on its own for it (grenades only on your `G`, the menu or a flash entry; heard noises used to empty its grenades on arrival). Even sweeping (`R`) or attacking, a group of your army only throws on its own at a foe seen less than `STRAT_NADE_FRESH` s ago (`group.contact.seen`), one man per `STRAT_NADE_GAP` (`group.nadeAt`): sweeping used to make each member throw at his stale `lastKnown`. The leader moves with `leadTo` (path, `waitsForGroup`, `SQUAD_PACE` + `doorPause` unless `rush`, the order is an attack, or a fresh seen contact), arrives at `STRAT_ARRIVE` (or at the end of its path within 1.2 U) and then takes the next queued order or holds; `holdStep` keeps it within `STRAT_LEASH`. Followers use `followStep`, which for a halted `hold` order lines them up abreast (`SQUAD_LINE`, places fixed once per order in `hold.line`, the followers sorted left to right by where they stand) facing `hold.angle`. `trackFoe` follows an attacked foe while it is `visible` to the army. `stackOrderStep` (both camps; without room in front of the door the group just walks through) walks the leader to `doorFront`, then `formStack(…, cmd = true)` with `stackTactic` (`'choose'` → `'wait'`; forced `'flash'`, `'frag'` or `'charge'` while the team still has one, else `'wait'`; `'auto'` = `pickEntry(…, true)`), lets `updateAiStack` run the entry (in place it waits for the door buttons, `stackChoose`), then holds at `doorInside`.

Rendering: the sidebar is a band of its own (`STRAT_PANEL` CSS px, `#stratPanel` full height): `Renderer.viewW()` is the canvas width minus it in strategy, and `fitZoom`, `clampCam`, `stratCamera` (centring, zoom toward the cursor, edge scrolling), `viewRect` and the menus frame the map within it; `drawStratPanel` paints the band's background on the canvas (under the minimap), and `UI.panelHit` counts the whole band as the panel. `#stratCmds` shows the orders section only while a group is selected. `Renderer.fitZoom` gives strategy a free zoom between `zoomMin` (whole map) and `zoomMax` (the on-foot framing), starting at `STRAT_VIEW`; `stratCamera` handles keys, edge scrolling (pointer locked, `renderer.locked`), zoom toward the cursor, `strat.camTo` and `clampCam`. `drawStratUnder` (rings), `drawStratOrders` (paths, markers, after the fog), `drawStratScreen` (badges, health bars, selection box, pause frame) and `drawStratCursor` replace the crosshair, vignette and heard arcs; names are hidden below 1.5× zoom. `drawMinimap` stores `miniRect`, draws the viewport and selected units; in strategy it fits inside the sidebar slot `#stratMini` (`renderer.miniSlot`, from `UI.miniSlot`); `aimWorld` maps the cursor through the minimap when over it. `stratCamera` does not edge-scroll over the sidebar (`renderer.overUi`) except against the right edge; `drawStratCursor` shows the grenade target (`FRAG_RADIUS` for a frag) while `nadeAim` is set. UI: `#hud.strategy` hides `#hpBox` / `#weaponBox` and shows `#stratPanel`, a right sidebar (`UI.updateStrategy`): `#stratArmy` (a `.scard` button per group, its type and `stratStatus`), `#stratCmds` (`.scmd` buttons from `stratCommands`), the minimap slot and help. The pointer is locked, so clicks reach the canvas, not the buttons: `main.js` asks `UI.panelHit(x, y)` (`elementFromPoint` under the drawn cursor; the panel itself and `#stratMini` let clicks through to the map) and calls `stratCommand` instead of passing the click on, and `UI.hoverAt` marks the hovered button (`.hover`); with the pointer free, the panel's own `mousedown` does the same. The briefing replaces the gear with `armyList` and `UI.commandList`; `#waveBanner` shows the tactical pause.

**Strategy assault** (`'strategyAssault'`, `MODES[mode].defense`, also `strategy`, `war` and `squads`, on `WAR_LEVELS`, police only, its own mode card): the strategy commander and three ops trinômes against no army but `DEFENSE_RATIO` × 9 armed men posted like assault suspects (`game.defense`, `war.defense = { total }`). `loadLevel` draws their posts with `buildPosts(quiet, n, true)` (`open`: outdoor grid too, ordered by a random key weighted 1 indoors, `DEFENSE_OUTSIDE[0]` outdoors within two fine cells of a wall or prop, `DEFENSE_OUTSIDE[1]` in the open), `quiet = defenseQuiet(home)` (every fine cell within `DEFENSE_CLEAR` of the home base centre), makes them plain `Enemy` (`DEFENSE_WEAPONS`, `DEFENSE_STATS`: `updateEnemy`, posts, `DEFENSE_PATROLS` patrols, general alarm, blind fire), and `startWar` spawns no enemy slot and gives the three ops groups one shared `buildSectors` list (`pingpong` off, so `pickSector` splits it between them). `updateWar` sets an annihilated trinôme's `respawn` to `Infinity` (it never comes back) and never prunes bodies; `checkEnd` has its own branch (no time limit: lose when no mate is alive, win when no enemy is `Game.active`), as do `scoreReport`, the HUD objective (the timer counts up), the briefing (`UI.defenseNote` instead of `campRow`, `commandList(armed, defense)`), the map list and the end screen. Balance comes from scratch simulations with the trinômes left to sweep on their own: with the trinômes' militant stats and AKs they killed a third of the defenders and lost in under 40 s; with assault suspects they won in 40–100 s; the current values win about four games in nine, narrowly either way.

## Escort mode

`'escort'` plays its own maps (`ESCORT_LEVELS`): the team escorts a VIP from point A (`'A'`, `map.vipStart`) to the extraction zone, point B (a block of `'Z'` cells: `map.goal = { cells, cx, cy }`, `map.goalAt`, `GameMap.inGoal(x, y)`). In `loadLevel` the VIP (`Vip extends Hostage`, in `js/entities.js`: `vip: true`, `VIP_HP` hit points, a soft vest `VESTS.vestL`, `style = STYLE_VIP`) is pushed into `game.hostages` — so bullets, frags, charges, door frames, `lineOfFireClear` and vision treat him like a civilian — and kept in `game.vip` (null in other modes); he starts escorted by the player (`takeCharge`). The player starts one cell from A toward B (`escortStart`), the mates form around him; `escortQuiet` (A's room plus `GOAL_MARGIN` around the zone) replaces the assault entry room for `buildPosts`, `buildPatrols` and `clearZone` (which never moves the VIP). Locks, patrols, alarm, charges, fiber, surrender, power cut, vests and shields work as in assault. Differences from a hostage: `H` toggles follow / wait (kneeling, `toggleEscort`), he never exits through a breach (`exitFor` is skipped), `Game.damage` gives him hit points instead of the hostage wound rule (`wounded` at half health slows him; `stats.vipHits` counts the team's hits), and when his escort dies he keeps `lostEscort` so `takeOver` hands him to the new player. Suspects target him too: `enemyCombat` passes `[...ops, vip]` to `acquireFor`, which returns him first whenever he is in view; a suspect already engaging an op switches to him as soon as it sees him (`VIP_SWITCH`, the turn-over delay). `updateEscort` (from `step`) sets `game.escort.safe` once he stands in the zone; `checkEnd` then wins, and loses if he dies or the whole team is down — remaining suspects don't matter. `scoreReport` has an escort branch (VIP health, team, no general alarm, penalties for team hits on the VIP). The renderer paints the zone and A on the floor (`Sprites.paintGoal`, `paintStart`), pulses B on the minimap even unexplored (`drawGoalMini`), labels the VIP; the UI shows his health and the compass direction of B (`UI.compass`) in the objective line, a VIP row in the squad box, a route plan in the briefing (`routePlan`; `UI.drawPlan` draws A and B instead of breach rings for maps that have both).

## Adding a mission

Append an entry to the mode's list in `js/levels.js`: `LEVELS` (hostage buildings shared by assault and siege, give them a `siegeBriefing`), `ASSAULT_LEVELS` / `SIEGE_LEVELS` (one of the two only), `ESCORT_LEVELS`, `SQUAD_LEVELS` or `WAR_LEVELS`, with the fields `{ name, briefing, enemyWeapons, map }` (trinômes and war maps need no `enemyWeapons`; their `briefing` describes the ground and is appended to the mode's text). Records are keyed by index (`breach.best.<mode>.<i>`), so append rather than insert. The map legend is at the top of that file and in the README:
- `#` wall, `D` closed door, `S` player spawn (fallback when a map has no breach), `H` hostage.
- `X` exterior door, `W` window: entry points from outside. Give every map several, including at least one of each, and keep enemies and hostages out of every room a breach opens into (the tests check it).
- `E` enemy with a random facing; `^ v < >` enemy with a fixed facing.
- Escort maps only: `A` the VIP's start, `Z` the extraction zone (a block at least three rows deep, so the trailing VIP gets in), no `H`, nobody in A's room. 
- Total war maps only: `1` and `2` the two bases (blocks roomy enough for three trinômes), no breach, no `E`/`H`, interior doors clear of props one cell each side (tested). Draw them symmetric. A prop covers the fine cells right of and below its ASCII cell, so a mirrored prop sits one fine cell off its mirror: check the gaps it leaves against walls and doors on the mirrored side.
- Trinômes maps only: at least four breaches, far enough apart that the opponents' two enter out of sight of any chosen one (`startSquads`), no `E`/`H`.
- Floors: `. , : ; = %` (concrete, parquet, tiles, carpet, marble, diamond plate), and outdoors `" _ + -` (asphalt is `FLOOR` 9). A new floor needs an entry in `FLOOR`, a painter in `Sprites.paintFloor` and a colour in `MINI_FLOORS`.
- Props: `c B T p b k` plus `s r a R P C` (sofa, shelving, locker, server rack, pallet, counter), and the low cover `g` sandbags, `m` low wall (`p.nb` holds the same-prop neighbours, so a row draws as one wall) and `V` car (a two-by-four block, cars never touching). A new prop needs `PROPS`, a case in `Sprites.paintProp`, and `PROP_AGAINST_WALL` if it has a back.
- A lone `#` inside a room is a pillar.
- A space is outside the building.
- Outdoor maps (`outdoor: true`, larger, no void): the whole rectangle is walkable ground — `"` grass, `_` gravel, `+` terrace paving (`OUTDOOR_FLOORS`) — bounded by `h` hedges (wall tiles, `map.hedgeAt` for drawing), with `t` trees and `~` pool cells as props (`p.edges` draws the coping). The entries are `O` cells on the map edge (`addBreach('gate', ...)`, inward from the nearest edge, labelled « Entrée … »); a `D`/`X`/`W` with floor on both sides is no breach, just a door or window onto the garden. `buildPosts` never draws a post on outdoor ground, so enemies and hostages stay under a roof (the garden is every gate's entry room). The tests require at least three gates and every breach a gate on outdoor maps.

On every map, keep one cell free of props on both sides of every interior door, along the passage (tested on all maps): a prop corner there snags a following hostage, VIP or squad file. Keep spawns clear of furniture (a spawn needs `circleFree(12)`) and leave at least two map rows between rows of racks or shelves: with a single map row the aisle is 32 px wide and agents (radius 11) barely fit.

A total war battle ends after `WAR_TIME`: won if your army killed more, lost if fewer, drawn otherwise. An escort mission is won when the VIP enters zone B alive, and lost if he dies or the whole team is down. An assault mission is won as soon as every enemy is dead or cuffed; escorting hostages out is optional (it keeps them safe). It is lost if the whole team is down (the player's death alone hands control to a mate) or any hostage dies (in siege mode, only once no hostage is left alive in the player's hands).
